# Информативные подписи и семантические легенды Presentation

Документ относится к ветке `release/1.2.2` форка `f2re/SatDump`.

## Зачем это нужно

Обычная подпись вида «False Color», перечень каналов и техническая формула не
объясняют пользователю, что именно показано на снимке. Новый семантический слой
добавляет к каждому Presentation-продукту четыре ответа:

1. **Что это за продукт?** — русское операционное название.
2. **Для чего он предназначен?** — краткое назначение в верхней панели.
3. **Как читать цвет?** — категориальная, непрерывная или компонентная легенда.
4. **Где пределы интерпретации?** — обязательные замечания без ложной физической
   определённости.

Minimal остаётся одной строкой. Полное объяснение выводится только в
`_annotated_presentation.png` и JSON-паспорте.

## Что появляется в верхней панели

Presentation перестраивает технические поля в прикладной порядок:

```text
Назначение | Данные | Режим | Каналы | Физика | Обработка |
Проекция | Приём | Дискретизация | NORAD | Подготовка | Ориентация
```

Пример для Night Microphysics:

```text
Метеор-М №2-4 / МСУ-МР
Ночная микрофизика облаков
01.09.2026 · 06:45:58–06:57:54 UTC · нисходящий пролёт
Назначение: туман, низкая и высокая облачность ночью |
Данные: качественный RGB-композит | Режим: ночь |
Каналы: 6 (11,9 мкм), 5 (10,8 мкм), 4 (3,7 мкм)
```

Техническое поле `Вариант` переименовано в более понятное `Подготовка`.

## Четыре типа обработчиков

Аудит и renderer рассматривают каждый preset по фактическому обработчику.

### Формула `equation`

- для трёх или четырёх выходов показывается состав R/G/B(/A);
- для известного продукта дополнительно показывается практическая расшифровка
  цветов;
- для одного калиброванного выхода строится физическая шкала;
- если диапазон неизвестен, SatDump не придумывает числовые деления.

### Таблица цветов `lut`

- при наличии `calib_cfg.min/max` строится непрерывная шкала;
- цвета берутся непосредственно из используемого LUT-файла;
- если физический диапазон не задан, выводится честная качественная легенда с
  именем LUT и предупреждением.

### Скрипт `lua`

- известные продукты, например температура поверхности моря, получают
  курируемую физическую легенду;
- для неизвестного скрипта показываются входные каналы, имя Lua-файла,
  назначение и ограничение: точная логика задаётся кодом скрипта.

### Обработчик `cpp`

- для известных тематических обработчиков применяется профиль;
- неизвестный обработчик получает состав входов и русское объяснение без
  выдуманного соответствия цветов явлениям.

## Семантические профили

Каталог расположен здесь:

```text
resources/presentation/composite_profiles_ru.json
```

Профиль может задавать:

- русское название;
- назначение;
- режим `день`, `ночь` или `круглосуточно`;
- тип данных;
- категориальные цвета;
- физический диапазон и единицы;
- комментарии и ограничения;
- правила совпадения по названию, файлу описания, LUT, Lua, C++ или прибору.

В поставку включены профили для:

- естественных и ложных цветов;
- AVHRR 3a-2-1 и облачного RGB 1-2-4;
- дневной и ночной микрофизики;
- типов и фазы облаков;
- пыли и вулканического пепла;
- воздушных масс и водяного пара;
- разностей атмосферного окна;
- температур облачной поверхности и усиленного ИК;
- температуры поверхности моря;
- пожаров и тепловых аномалий;
- NDVI и NDWI;
- снега и льда;
- MCIR и эвристики вероятности осадков;
- сельскохозяйственных, геологических и батиметрических RGB;
- перистой и конвективной облачности;
- облачности на внешней картографической подложке.

Если профиль не найден, используется безопасный универсальный fallback. Поэтому
каждый композит получает объяснение, но SatDump никогда не назначает ему
категориальную или числовую шкалу без оснований.

## Пример категориальной легенды

```json
{
  "presentation": {
    "semantic_profile": "night_microphysics"
  }
}
```

Renderer покажет цветовые классы, назначение, ограничения и сохранит формулы
компонентов R/G/B в примечаниях.

## Пример физической шкалы

Для одноканального продукта:

```json
{
  "channels": "cch5",
  "calib_cfg": {
    "cch5": {
      "type": "temperature",
      "min": 180,
      "max": 320
    }
  }
}
```

Presentation автоматически формирует:

- заголовок `Яркостная температура`;
- единицу `K`;
- числовые деления;
- градиент из LUT, если LUT задан;
- предупреждение, что интерпретировать следует значение, а не только цвет.

## Ручное переопределение

Явная `presentation.legend` всегда имеет приоритет над автоматическим профилем:

```json
{
  "presentation": {
    "title": "Температура облачной поверхности",
    "semantics": {
      "purpose": "Контроль холодных вершин конвективных облаков",
      "mode": "круглосуточно",
      "data_kind": "калиброванная ИК-шкала"
    },
    "legend": {
      "kind": "continuous",
      "title": "Яркостная температура",
      "unit": "°C",
      "min": -90,
      "max": 10,
      "ticks": [-90, -70, -50, -33, -10, 10],
      "colors": [
        "#090A0D",
        "#B1252B",
        "#F3B43A",
        "#4FB76B",
        "#3C79C7",
        "#F3F4F5"
      ],
      "notes": [
        "Температура верхней границы облаков требует отдельного атмосферного профиля."
      ]
    }
  }
}
```

Можно принудительно выбрать профиль:

```json
{
  "presentation": {
    "semantic_profile": "dust_ash_rgb"
  }
}
```

Автоматическую семантику для отдельного preset можно отключить:

```json
{
  "presentation": {
    "auto_semantics": false
  }
}
```

## Аудит всех композитов

Сценарий проходит по **каждому** `rgb_composites` во всём `satdump_cfg.json`, а
не только по МСУ-МР:

```bash
python3 scripts/presentation/audit_composites.py \
  --config satdump_cfg.json \
  --profiles resources/presentation/composite_profiles_ru.json \
  --resources-root resources \
  --output build/presentation-composites-audit.md \
  --json-output build/presentation-composites-audit.json \
  --strict
```

Для каждого композита отчёт содержит:

- прибор;
- название preset;
- `equation`, `lut`, `lua` или `cpp`;
- выбранный профиль;
- тип легенды;
- источник решения;
- структурные предупреждения.

Отчёт генерируется в GitHub Actions и публикуется отдельным артефактом.

## Правила научной корректности

1. RGB-цвет не объявляется самостоятельной физической величиной.
2. Яркостная температура не называется высотой верхней границы облаков.
3. Эвристический цвет вероятности осадков не называется интенсивностью осадков.
4. Пожарный RGB не отличает пожар от другого высокотемпературного источника без
   дополнительной проверки.
5. NDVI/NDWI сопровождаются ограничениями облачности и атмосферных эффектов.
6. Подложка MCIR явно отделяется от измеренного спутником сигнала.
7. Для неизвестного алгоритма показывается безопасное объяснение, а не
   выдуманная легенда.
