# 🖼️ Плашки, легенды и паспорт продукта

## 1. Архитектурный принцип

Presentation renderer — отдельный финальный этап:

```text
сырые данные
  → декодирование
  → калибровка/композит
  → геометрическая коррекция
  → проекция и карта
  → исходный научный продукт
  → оформленная копия PNG + JSON
```

Исходный растр не масштабируется и не заменяется.

## 2. Почему плашки не добавляются в GeoTIFF

Верхняя и нижняя панели увеличивают высоту изображения. Если считать их частью
геопривязанного растра, пиксели плашки будут ошибочно интерпретироваться как
участок земной поверхности.

Поэтому сохраняются отдельные файлы:

```text
product_projected.tif              научный геопривязанный продукт
product_projected_annotated.png    оформленная публикационная копия
product_projected_annotated.json   паспорт оформления
```

## 3. Приоритет исходного изображения

Renderer выбирает наиболее информативный доступный вариант:

1. проекция с картографическими слоями;
2. геометрическая коррекция с картой;
3. карта без геометрической коррекции;
4. геометрически исправленный растр;
5. исходный композит.

Для каждого композита создаётся одна основная оформленная копия, а не набор
почти одинаковых PNG.

## 4. Верхняя панель

### Обязательный минимум

- спутник/источник;
- прибор;
- название продукта;
- интервал наблюдения UTC;
- используемые каналы.

### Дополнительные поля

Показываются только при наличии данных:

- NORAD ID;
- направление пролёта;
- максимальная высота;
- частота радиолинии;
- частота дискретизации;
- проекция;
- вариант обработки;
- SNR;
- потери пакетов/строк;
- интегральная оценка качества.

### Два разных диапазона

Не смешивайте:

```text
137,9 МГц          радиочастота приёма
10,5–11,5 мкм      спектральный диапазон прибора
```

Они должны иметь разные подписи.

## 5. Нижняя панель

Поддерживаются четыре режима.

### 5.1 Непрерывный

Для количественной величины:

- яркостная температура;
- отражательная способность;
- альбедо;
- радианс;
- высота;
- водность;
- интенсивность осадков.

Содержит цветовую шкалу, деления, единицу и примечания.

### 5.2 Категориальный

Для классов:

- тип облачности;
- фаза облака;
- снег/лёд/вода;
- классы осадков;
- маски качества;
- «не определено».

Каждому классу соответствует фиксированный цвет и подпись.

### 5.3 Composite/RGB

Для условного многоканального синтеза:

```text
R — канал или формула
G — канал или формула
B — канал или формула
```

Отображаются:

- входные каналы;
- центральные длины волн;
- калиброванные величины;
- исходные выражения;
- LUT/Lua/C++-алгоритм;
- эквализация, инверсия, нормализация, баланс белого.

### 5.4 Без числовой шкалы

Даже если физическую легенду построить нельзя, footer не остаётся пустым. Он
перечисляет каналы и объясняет условность цветов.

## 6. Автоматический анализ RGB

Для выражения из трёх компонент:

```text
expr_R, expr_G, expr_B
```

анализатор:

1. разделяет выражение по запятым верхнего уровня;
2. сопоставляет токены с реальными именами каналов `ImageProducts`;
3. различает `ch...` и `cch...`;
4. получает длину волны из wavenumber;
5. добавляет тип калибровки;
6. показывает формулу целиком.

Разность:

```text
cch8-cch9
```

распознаётся как два канала, а не как одно имя.

## 7. LUT, Lua и C++-композиты

Для нелинейного алгоритма невозможно автоматически утверждать, что конкретный
цвет соответствует одной физической величине.

Footer показывает:

- список обнаруженных входов;
- название LUT/скрипта/алгоритма;
- предупреждение о многозначности;
- экспертные notes из пресета.

## 8. Научная терминология

### Яркостная температура

Одноканальный ИК-продукт обычно следует подписывать:

```text
Яркостная температура, K
```

### Температура верхней границы облаков

Название допустимо только при наличии отдельного алгоритма восстановления,
который обоснованно оценивает физическую температуру верхней границы облака.

Простая калибровка ИК-канала в кельвины не равна полноценному cloud-top
temperature retrieval.

### Тип облачности

Тип облачности — категориальный многоканальный алгоритм. Нельзя называть так
обычную температурную раскраску.

## 9. Одна палитра — два применения

Правильная модель:

```text
ColorMapSpec
  ├─ окрашивает значения продукта
  └─ строит легенду
```

Неправильно поддерживать отдельно:

- LUT для изображения;
- похожую, но ручную шкалу для footer.

Они неизбежно разойдутся.

## 10. UI/UX-система

### Палитра по умолчанию

| Назначение | Цвет |
|---|---|
| основной фон | `#0E1624` |
| вторичная поверхность | `#172235` |
| граница | `#2A3A50` |
| основной текст | `#F3F7FB` |
| вторичный текст | `#AAB8C8` |
| акцент | `#4EC7E8` |
| предупреждение | `#FFB454` |
| ошибка | `#FF6B6B` |

### Иерархия

1. спутник и прибор;
2. название продукта;
3. время и параметры пролёта;
4. технические детали;
5. легенда;
6. branding.

### Сетка

Базовая кратность:

```text
8 / 16 / 24 / 32 / 48 px
```

Размеры масштабируются относительно ширины растра и ограничиваются минимальным
и максимальным коэффициентом.

### Что не использовать

- тяжёлые градиенты панели;
- стеклянные эффекты;
- крупные тени;
- много декоративных иконок;
- разноцветные рамки;
- текст поверх спутникового растра;
- мелкий шрифт ради размещения всех метаданных.

## 11. Адаптивность

Renderer:

- измеряет UTF-8 текст тем же шрифтом, которым рисует;
- переносит строки;
- меняет высоту header/footer;
- использует одну или две колонки категорий;
- центрирует подписи шкалы, не выпуская их за края;
- не ресемплирует исходное изображение.

## 12. Кириллица

Используется поставляемый с SatDump шрифт:

```text
resources/fonts/Roboto-Medium.ttf
```

Тестируйте:

- русский;
- английский;
- знак микрометра `мкм`/`µm`;
- градусы;
- длинное тире;
- отрицательные значения.

## 16. Паспорт `satdump.presentation/1`

JSON содержит точные данные, использованные при рендеринге. Это позволяет:

- повторно оформить архив без декодирования;
- проверить соответствие подписи и продукта;
- индексировать архив;
- генерировать веб-карточки;
- проводить аудит алгоритма.

## 17. Контроль качества макета

Перед выпуском пресета проверьте минимум:

1. 720 px по ширине;
2. 1280/1920 px;
3. длинную узкую полосу;
4. 4K;
5. русский и английский текст;
6. отсутствие данных;
7. очень длинное название продукта;
8. 10+ категорий;
9. отрицательные и дробные ticks;
10. совпадение цвета контрольного значения на карте и шкале.
