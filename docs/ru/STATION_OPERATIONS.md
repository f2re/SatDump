## Главные различия

**Сборка** подготавливает программу на машине с инструментами и интернетом. **Упаковка** собирает готовые компоненты в проверяемый архив. **Установка** автономно разворачивает этот архив на Astra. **Деплой** передаёт его по разрешённому SSH-маршруту и вызывает тот же установщик.

Обычный push не устанавливает код на станцию. `[station-release]` и `[station-deploy]` — явные запросы, работающие только с соответствующим workflow и его фильтрами. PR не получает право публиковать или развёртывать пакет.

## Минимальный контроль

```bash
sudo systemctl is-active satdump-worker satdump-web
sudo satdump-station status
sudo journalctl -u satdump-worker -u satdump-web -n 100 --no-pager
```

Проверяйте не только активность процессов, но и успешное новое контрольное задание. `health.json` требует анализа JSON; HTTP 200 не гарантирует исправность воркера.

> [!WARNING]
> Не удаляйте SQLite, не меняйте glibc, не выдавайте `chmod 777` и не отключайте проверку SSH host key как способ исправить неизвестную ошибку. Сначала сохраните версию, конфиг и журнал, затем следуйте таблице диагностики.

В новых пакетах эта карта доступна как `OPERATIONS.ru.md`; подробные инструкции сохраняются рядом в `docs/`. Политики Astra и приёмка реального источника остаются отдельной обязанностью администратора.
