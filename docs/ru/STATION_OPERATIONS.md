# SatDump Station: сборка, выпуск и управляемое развёртывание

Основная инструкция: `STATION_ASTRA16.md` в исходниках, `START_HERE.ru.md` в бинарном пакете. Этот файл включён в пакет как `OPERATIONS.ru.md`.

## Что выполняется автоматически

`station-astra16.yml`: тесты очереди/HTTP на Ubuntu и реальном Python 3.5/Pillow в Stretch → сборка glibc224 → проверка всех ELF → упаковка → повторный запуск распакованного пакета без сети → офлайн-установка без запуска systemd в тестовом контейнере → артефакт. Публикация и SSH-развёртывание выполняются только после успеха обязательных этапов.

Тесты содержат синтетические данные и подмену вызова native() в отдельных проверках адаптера. Их успех не является доказательством декодирования реальной IQ-записи. Проверка синтаксиса JavaScript также не является автоматизированной приёмкой браузерного интерфейса.

## Выпуск в этой же ветке

Обычный push запускает быстрые проверки. Commit с `[station-release]` дополнительно собирает и публикует отдельный предварительный релиз. Commit с `[station-deploy]` собирает и устанавливает пакет на настроенный SSH-хост. Два маркера можно использовать вместе. Запросы PR никогда не публикуют и не развёртывают пакет.

Для повторного выпуска без изменений кода измените файл-заявку, попадающий под фильтр путей:

```bash
git switch release/1.2.2
git pull --ff-only
printf '%s\n' "$(date -u +%Y-%m-%dT%H:%M:%SZ)" > config/station/release-request.txt
git add config/station/release-request.txt
git commit -m 'ci: request station package [station-release]'
git push origin HEAD:release/1.2.2
```

Для выпуска с установкой используйте сообщение с обоими маркерами. Пустой commit недостаточен: у workflow есть фильтр изменённых путей. Новая версия не перезаписывает ранее опубликованный тег или его вложения. Новый push отменяет устаревший прогон этой ветки; ручные прогоны не отменяются автоматически друг другом.

`workflow_dispatch` также описан в YAML. GitHub требует присутствия такого workflow в default branch для ручного запуска. Пока default branch остаётся `master` без этого файла, используйте указанные push-маркеры либо локальный `station.sh deploy`; менять default branch для работы станции не требуется.

## Настройка автодеплоя

В GitHub Environment `astra16-station` задайте секреты:

| Секрет | Значение |
|---|---|
| `ASTRA16_DEPLOY_TARGET` | Явный адрес `user@host` |
| `ASTRA16_DEPLOY_KEY` | Приватный SSH-ключ выделенного пользователя развёртывания |
| `ASTRA16_KNOWN_HOSTS` | Заранее проверенная запись ключа целевого SSH-сервера |

Пользователя, его SSH-доступ и разрешение `sudo -n` на установку настраивает администратор. Установщик не создаёт пароли и не редактирует sudoers. Проверка SSH-ключа сервера никогда не отключается. На исполнителе создаются временные файлы ключа и known_hosts; существующий `~/.ssh/known_hosts` не перезаписывается. Настройте обязательное согласование Environment, когда этого требует процедура эксплуатации.

Для закрытой ЛВС укажите репозиторную переменную `ASTRA16_DEPLOY_RUNNERS`, например:

```json
["self-hosted", "linux", "satdump-deploy"]
```

Это метки заранее установленного доверенного GitHub Actions runner, имеющего маршрут до станции. Сам runner должен удовлетворять требованиям GitHub Actions; он не обязан находиться на старой Astra. По умолчанию используется `ubuntu-22.04` на GitHub: такой исполнитель не получает доступ в вашу ЛВС автоматически. Выделенный runner не используйте для недоверенных задач из чужих репозиториев.

Ручное развёртывание с доверенной машины в сети станции:

```bash
./station.sh deploy /путь/к/satdump-....tar.gz operator@192.0.2.10
```

Адрес выше демонстрационный. Рядом с архивом обязателен его `.sha256`. На станции вызывается тот же `install.sh`, с сохранением конфигурации и данных, проверкой служб и возвратом предыдущей версии при провале проверки запуска. При первом развёртывании сайт слушает только `127.0.0.1:8090`; публикация в ЛВС включается администратором отдельно.

## Что именно означает «офлайн»

Начальная сборка на машине с интернетом скачивает исходники компилятора и зависимости. Автономными являются перенос, установка и работа готового пакета на Astra: там не требуются apt/pip/npm/Docker. Первичная сборка всего пакета без сети из неполного кеша не обещается.

Для физически изолированной станции без сетевого маршрута SSH-автодеплой невозможен по определению: перенесите тот же проверенный архив на носителе и выполните `sudo ./install.sh`. Это не другой вариант программы, а тот же пакет.

## Приёмка на целевой Astra 1.6

После установки проверьте `sudo satdump-station status`, `systemctl status satdump-worker satdump-web` и сайт. Подайте сначала известный PNG/JSON, затем полный контрольный `product.cbor` с каналами и `.ready`, затем контрольную IQ-запись с правильным профилем. Сопоставьте цветосинтез с обычным запуском этого же SatDump и убедитесь в сохранности исходников.

Перезагрузите станцию: службы должны подняться, незавершённые задания вернуться в очередь, ранее опубликованные материалы остаться доступными. Проверьте обновление вторым пакетом и `sudo satdump-station rollback`. Отдельно проверьте права смонтированной входной папки, политики мандатного доступа и сетевой экран. Эти проверки нельзя заменить контейнерным тестом Debian.
