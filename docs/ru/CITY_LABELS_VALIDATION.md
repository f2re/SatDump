# Приёмка русских названий городов в C++ и дистрибутиве

Основная ветка этой доработки — `release/1.2.2`. Названия не переводятся при
отрисовке: `name_ru` копируется из закреплённого Natural Earth, исходное `name`
сохраняется. Отсутствующие переводы остаются исходными названиями.

## Что проверяется

`src-testing/city_names_runtime_test.cpp` собирается с настоящим `satdump_core`.
Он читает полный установленный GeoJSON и отчёт импорта, сравнивает каждую
русскую строку с результатом выбора подписи, проверяет наличие всех используемых
глифов в `font.ttf` и `Roboto-Medium.ttf`, а затем действительно растеризует все
русские названия обоими шрифтами. Пустое изображение или отсутствующий глиф —
ошибка, а не успешная проверка.

Восемь записей настоящего каталога (Москва, Санкт-Петербург, Норильск, Ноябрьск,
Комсомольск-на-Амуре, Ханты-Мансийск, Кишинёв, Париж) пропускаются через штатный
проецируемый отрисовщик. Точки разложены по диагностической сетке: это стенд
подписей, не географическая карта. Сверяются точные строки и пиксели текста
вне маркеров. Старый `drawProjectedCitiesGeoJson` проверяется сравнением
растров с эталоном из тех же русских строк. Оба пути используют общий
`resolve_city_name`; прежнее прямое чтение `nameascii` устранено.

Дополнительно вызывается настоящий `OverlayHandler::apply`. Проверяются
сохранение `cities_locale` в конфигурации, приоритет `name_ru` над старым
`cities_label_field="name"`, смена `ru → en → ru`, сброс кэша и повторяемость
пикселей. Результаты сохраняются в PNG и `runtime-report.json`.

## Исходники, установка и упаковка

`build-native.sh` при включённых тестах обязательно запускает старый
`map-label-test` и новый полный C++ тест. После установки повторяется прогон
установленного проверочного исполняемого файла с установленным `satdump_core`.
Отсутствующий исполняемый тест считается ошибкой. Явный `--without-tests`
по-прежнему предназначен только для сборки без приёмки; CI его не использует.

`verify_installed_city_names.py` без сети сверяет байты GeoJSON, отчёта и двух
шрифтов между исходным и установленным деревом. Дополнительно пересчитывается
контрольная сумма содержимого каталога из отчёта. Повреждённый или устаревший
ресурс не может пройти проверку только за счёт наличия файла.

Оба упаковщика — glibc 2.24 и glibc 2.28 — требуют тот же прогон **до создания
архива**. В архив входят проверочный исполняемый файл и результаты в
`validation/city-labels/`. Для glibc 2.28 тесты включены и в сборке desktop.
CI официального Astra UBI 1.7 повторяет C++ тест на распакованном архиве
с `--network none`. Это не заменяет аппаратную приёмку приёмника на станции.

Проверочный процесс выполняет поиск ресурсов из пустого рабочего каталога:
дерево исходников не может незаметно подменить установленный каталог.

## Воспроизведение

```bash
python3 -m unittest discover -s tests/maps -v
bash scripts/astra/build.sh --mode native --profile headless --install

# Проверка уже установленного дерева; Python 3.5+, без сторонних пакетов.
bash scripts/maps/validate_city_runtime.sh \
  "$PWD/resources" /путь/к/satdump-prefix /tmp/satdump-city-validation

# Только C++-отрисовка, без Python и сети:
LD_LIBRARY_PATH=/путь/к/satdump-prefix/lib \
  /путь/к/satdump-prefix/bin/satdump-city-names-runtime-test \
  /путь/к/satdump-prefix/share/satdump/resources /tmp/satdump-city-validation
```

В CI `presentation-1.2.2.yml` сохраняются отдельные артефакты
`city-runtime-astra-1.6` и `city-runtime-astra-1.7` с результатами исходного и
установленного деревьев. Названия этих двух заданий обозначают профили
совместимости на Ubuntu, а не выполнение внутри нативной Astra. Нативный UBI
и переносимый архив проверяются отдельными заданиями; `skipped` не является
подтверждением их прохождения.

Проверка импорта в `city-names-ru.yml` сначала проверяет уже закоммиченный
каталог, чтобы последующая генерация в CI не скрывала забытый файл данных.
Обычные проверки не создают коммиты; запись разрешена только при ручном запуске.
