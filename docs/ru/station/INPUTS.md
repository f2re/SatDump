# 📥 03 · Входные файлы и завершение передачи

[← Архитектура](DATAFLOW.md) · [Оглавление](README.md) · [Настройки →](CONFIGURATION.md)

## 1. Выбрать вид источника

| `kind` | Единица задания | Действие | Что требуется |
|---|---|---|---|
| `image` | Один PNG/JPEG и соседний JSON | Подготовка веб-материалов | Реальная картинка поддерживаемого формата |
| `product` | Один непосредственный дочерний каталог | Повторная обработка каждого `product.cbor` | Все необходимые каналы и `.ready` |
| `pipeline` | Один файл записи/кадров | Явно настроенный конвейер SatDump | Правильные pipeline, input level, формат и параметры |

Один источник — одно понятное правило. Для Meteor IQ и NOAA кадров создавайте разные источники, а не маску `*.*` с одним декодером.

<a id="ready"></a>
## 2. Договор готовности: производитель и потребитель

**Надёжный вариант:** производитель пишет временное имя или каталог, завершает все файлы, а затем атомарно переименовывает результат и/или создаёт маркер готовности последним. Воркер не создаёт маркеры сам и не удаляет их после обработки.

| Вход | Маркер при `require_ready=true` |
|---|---|
| `image.png` | `image.png.ready` |
| `pass.cs16` | `pass.cs16.ready` |
| `products/pass-01/` | `products/pass-01/.ready` |

Файл `image.ready` **не равен** `image.png.ready`. JSON-паспорт `image.json` передаётся **до** маркера. Для многоканального пролёта `.ready` лежит в корне каталога пролёта, не рядом с каждым каналом.

После появления маркера всё равно действует окно стабильности. Неизменность размера и mtime в течение 30 секунд не отличает завершённую передачу от временно остановившейся: для медленных и сетевых копирований используйте маркер.

<a id="images"></a>
## 3. Готовые изображения

```text
inbox/images/
├── image.png
├── image.json             необязательный паспорт
└── image.png.ready        нужен только при require_ready=true
```

Без JSON снимок публикуется, но неизвестные метаданные не выдумываются. У картинки сохраняется оригинал; создаются отдельные превью. По одному RGB/PNG невозможно заново получить исходные спектральные каналы и достоверно пересчитать физический продукт.

Следующий пример — **описательный**, не доказательство происхождения и не замена паспорту реального renderer:

```json
{
  "schema": "satdump.presentation/2",
  "pass": {
    "satellite": "Контрольный источник",
    "instrument": "Контрольный прибор",
    "product": "Учебный пример, не наблюдение",
    "acquisition_time": "2026-09-08 12:00 UTC"
  },
  "legend": {
    "kind": "none",
    "notes": ["Синтетические данные; физическая интерпретация не задана."]
  }
}
```

Распознавание поля `schema` в стороннем JSON **не является проверкой подлинности**. В галерее это признак формата, а не криптографически подтверждённого происхождения.

Маски по умолчанию: `*.png`, `*.jpg`, `*.jpeg`, без учёта регистра. Проверяется реальный формат PNG/JPEG; переименование TIFF в `.png` не делает его поддерживаемым. Файлы с окончанием `.part`, `.tmp`, `.partial`, скрытые элементы и символьные ссылки не предназначены для обработки.

<a id="products"></a>
## 4. Сохранённый продукт SatDump

```text
inbox/products/
└── pass-20260908-1200/
    ├── dataset.json                 необязателен для обнаружения
    ├── MSU-MR/
    │   ├── product.cbor
    │   ├── channel-1.png
    │   └── остальные реальные файлы набора
    ├── другой-прибор/
    │   └── product.cbor и его данные
    └── .ready                       последний переданный файл
```

Имена каналов на схеме условные: сохраняйте **исходные имена**, на которые ссылается конкретный CBOR. Один непосредственный дочерний каталог `inbox/products` — один пролёт. Воркер рекурсивно ищет `product.cbor` внутри него. Структура `products/год/месяц/пролёт` без отдельной настройки корня объединит данные иначе, чем ожидает оператор.

Вся единица задания сначала копируется в `work`. Для каждого продукта вызывается `satdump reprocess`. Перед вызовом из рабочей копии удаляются старые `*_annotated*`, чтобы ранее оформленный PNG не был принят за новый результат. Исходный каталог не меняется.

Публикация требует хотя бы одного нового `_annotated_presentation.png` с паспортом `/1` или `/2`. Нулевой код возврата процесса без таких файлов не считается успехом. Если один прибор не дал результата, но другой дал, это ещё не означает полноту всех ожидаемых продуктов: проверяйте журнал и перечень выходов.

<a id="pipeline"></a>
## 5. Записи IQ и кадры

В поставляемой конфигурации есть **выключенный пример** `meteor_iq`. Фрагмент элемента `sources`:

```json
{
  "id": "meteor_iq",
  "kind": "pipeline",
  "enabled": false,
  "path": "/var/lib/satdump-station/inbox/meteor_iq",
  "patterns": ["*.cs16"],
  "pipeline": "meteor_m2x_lrpt",
  "input_level": "baseband",
  "options": ["--samplerate", "1024000", "--baseband_format", "s16"],
  "require_ready": true
}
```

Число `1024000` и формат `s16` относятся только к примеру. Перед `enabled=true` проверьте параметры своей записи, тип спутника, режим передачи, формат отсчётов и уровень входа. Не копируйте параметры наугад.

Вызов формируется как массив аргументов, без shell:

```text
engine/satdump PIPELINE INPUT_LEVEL COPIED_INPUT OUTPUT_DIR
  ...options... --offline --processing_config processing.json
```

Команды из соседних JSON не исполняются. Аргументы выбирает администратор. Поддержка конкретного декодера зависит от набора плагинов `reference` или `meteor`. Воркер не является самостоятельным SDR-приёмником.

## 6. Сетевая папка

SMB/NFS монтируются средствами ОС **до** чтения воркером. Процессу нужны чтение и проход по каталогам; запись в исходную папку ему не требуется. Состояние очереди, `work` и `public` оставляются локально.

```bash
findmnt /mnt/receiver
sudo -u satdump-station test -x /mnt/receiver
sudo -u satdump-station test -r /mnt/receiver/control.png
```

> [!WARNING]
> Пустой локальный каталог на месте отключённого сетевого монтирования может выглядеть как «нет новых файлов». В текущем коде нет проверки идентичности mountpoint или контрольного файла источника. Контролируйте монтирование отдельно; `sources` не гарантирует обнаружение всех отказов вложенных каталогов.

## 7. Повторные поступления и ошибки

JSON, пришедший после публикации картинки, создаёт новый снимок состояния и может дать вторую карточку. Изменение имени влияет на идентификатор; это не глобальная дедупликация по изображению. При изменении входа во время копирования задание помечается `superseded`, а новая стабильная версия будет обнаружена отдельно.

Один вход ограничен 10 000 файлами и суммарным `max_input_mb`. Для продукта временный файл с окончанием `.part/.tmp/.partial` мешает приёму всего набора. Исправляйте передачу у производителя; не создавайте `.ready` поверх недописанных каналов.
