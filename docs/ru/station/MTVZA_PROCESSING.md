# МТВЗА-ГЯ: обработка и диагностика

[Источники](INPUTS.md) · [Конфигурация](CONFIGURATION.md) · [UTC](UTC_AND_SCHEDULER.md)

## Вход и выход

Для микроволнового радиометра используется тракт `meteor_hrpt` либо `meteor_m_mtvza_dump` для соответствующего формата выгрузки. LRPT МСУ-МР не содержит обязательного набора МТВЗА. Сохранённый продукт передаётся целиком: `product.cbor` и растры каналов, на которые он ссылается.

В HRPT принимаются только полные последовательности счётчиков 2–26. Пропуск, повтор или перестановка кадра отбрасывают незавершённую строку; следующая полная строка принимается. Промежуточные 200 отсчётов накапливаются отдельно, поэтому они не перезаписывают соседнюю выходную строку. Сохранено прежнее 100-пиксельное окно и существующая геометрия HRPT. Расширение окна до 200 пикселей требует отдельной проверки геопривязки.

В выгрузке X-диапазона принимаются полные последовательности 1–51. Повтор завершающего кадра не создаёт новую строку. Неполный последний кадр файла не обрабатывается повторно из оставшихся байтов буфера. Результаты двух трактов помечаются `channel_layout=hrpt30` и `dump46`; номера каналов нельзя считать общей таблицей частот.

При отсутствии полных строк МТВЗА его `product.cbor` не создаётся, состояние прибора — `no_data`. При отсутствии данных всех приборов команда завершается с ошибкой. При повреждении части записи сохраняются полные строки с предупреждением о пропусках.

## Отчёты

`decode-status.json` рядом с `dataset.json` содержит число полных строк, пропущенных сканов, отвергнутых кадров и остаточных байтов. `processing-status.json` в каталоге прибора содержит созданные, пропущенные и неуспешные композиции. `dataset-processing.json` сохраняет исход обработки каждого продукта; отказ одного прибора не препятствует обработке остальных.

CBOR не считается доказательством готовности изображений. Пустые/нечитаемые каналы отмечаются отдельно. `satdump reprocess` возвращает ненулевой код при отсутствии продукции или частичной ошибке. Уже полученные пригодные файлы сохраняются. Метаданные и непустые растры записываются через временный файл; ошибка записи не превращается в успешный паспорт. Это защита от незавершённой записи, не замена резервированию при потере питания.

## Контроль полноты на станции

В элемент источника `sources` можно добавить:

```json
{
  "id": "meteor_channels",
  "kind": "product",
  "path": "/var/lib/satdump-station/inbox/products",
  "require_ready": true,
  "required_instruments": ["mtvza"]
}
```

Используются машинные идентификаторы, например `mtvza` и `msu_mr`, а не подписи карточек. Список задаётся в центральной конфигурации, включая активную ревизию API. Если обязательный прибор не дал проверяемых презентационных изображений, задание повторяется с существующими ограничениями очереди, затем переходит в `failed`. Изображения другого прибора не скрывают это отсутствие. После исправления причины доступен обычный `retry`.

При пустом списке обязательных приборов пригодная часть набора публикуется с `processing_quality.status=partial` и предупреждением в галерее. Для старого движка без отчётов полнота обозначается как непроверенная. Самостоятельная подмена прибора по имени каталога не выполняется.

Подробный отчёт станции: `logs/<job_id>.quality.json`. Краткое состояние последнего задания доступно в `worker.json` и `/health.json` как `last_result`; абсолютные пути и текст внутренних исключений в него не включаются.

Истечение тайм-аута и превышение лимита журнала не превращаются в успешную частичную публикацию. При штатной остановке службы задание возвращается в очередь без расходования попытки. При восстановлении очереди проверяется существование всех файлов опубликованного набора. Неполный набор переносится в приватный `work/quarantine-*`, затем восстанавливается из доступного источника; запись задания и его идентификатор сохраняются. Если источник удалён, восстановить потерянные данные автоматически невозможно. Карантин очищается администратором после проверки.

## Время и научная интерпретация

В выгрузке МТВЗА время набора вычисляется из доступных бортовых отметок, а не из `time(0)`. Если отметки отсутствуют, сохраняется неизвестное время. Имеющиеся преобразования бортового счётчика для М2-3/М2-4 помечены как `legacy_onboard_counter_conversion`: их точность требует проверки на реальной записи. Проекция выбирается только для указанного аппарата и только при наличии соответствующего файла; неподходящая проекция другого аппарата не подставляется.

Пять рецептов с прежними именами Soil Moisture, Vegetation, Microwave Airmass, Rainfall и Sea Ice сохранены для совместимости. Они выполняют комбинацию цифровых отсчётов и эквализацию контраста. Радиометрическая калибровка и алгоритмы восстановления физических величин не реализованы. Оформление показывает формулы и экспериментальный статус, а не классы осадков, града, сплочённость льда, влажность или биомассу. Защита действует и при старой пользовательской категорической легенде.

## Проверки

Из корня исходников:

```bash
python3 -m unittest discover -s tests/station -v
python3 scripts/docs/check.py
```

После сборки с `BUILD_TESTING=ON` выполняются `satdump-mtvza-reader-test` и `tests/meteor/test_native_products.py`. Они проверяют оба порядка байтов, два разных соседних скана, пропуски, дубли, восстановление, отсутствие каналов, HRPT и выгрузку X-диапазона. Данные синтетические: эти тесты не подтверждают калибровку, физическую интерпретацию цветов и точность геопривязки реальных наблюдений.
