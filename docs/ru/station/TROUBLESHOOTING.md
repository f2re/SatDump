## 1. Первые проверки

**Где:** установленная станция. Эти команды читают состояние; `logs` завершайте Ctrl+C.

```bash
sudo systemctl status satdump-worker satdump-web --no-pager
sudo satdump-station status
sudo journalctl -u satdump-worker -u satdump-web -n 150 --no-pager
df -h /var/lib/satdump-station
```

Уточните версию: `readlink -f /opt/satdump-station/current`, затем `PACKAGE-MANIFEST.json` этой версии. Сохраните ID проблемного задания. Для его native-журнала используйте файл `/var/lib/satdump-station/logs/<ID>.log`.

## 2. Симптом → причина → действие

| Симптом | Что проверить | Действие |
|---|---|---|
| «Это не готовый пакет» | Есть ли `engine/satdump` и `runtime/python` | Нужен бинарный архив станции, не Source code ZIP |
| Требуется GLIBC_2.28 | Не выбран ли Desktop-пакет Astra 1.7 | Использовать сборку glibc224; не заменять системную libc |
| Пакета Station нет в Releases | Статус `package` в соответствующем Actions run | Не путать прошедшие тесты с прошедшей сборкой; сохранить её журнал |
| Воркер активен, новых снимков нет | Правильный источник, `enabled`, маска, права, `.ready`, окно стабильности | Проверять по порядку от входа, не начинать с удаления БД |
| Папка продуктов игнорируется | Один дочерний каталог на пролёт, `product.cbor`, `.ready` в корне пролёта | Исправить расположение и завершить передачу |
| `Input changed` / `superseded` | Запись ещё меняется | Дождаться завершения; новый стабильный вход обнаружится отдельно |
| `No native presentation PNGs` | Каналы, `autogen`, полное оформление, реальный pipeline, журнал SatDump | Исправить рецепт или вход; старый PNG не подставлять вместо нового |
| `failed` остался после исправления | Исчерпаны попытки | Вызвать `retry --job ID`; при изменении рецепта новая версия ставится отдельно |
| Сайт работает, воркер не отвечает | `worker_alive`, systemd и журналы | HTTP 200 сам по себе не доказывает исправность воркера |
| Сайт виден только на самой Astra | `SATDUMP_HOST=127.0.0.1` | Явно включить bind для ЛВС и согласовать сетевой доступ |
| «Время наблюдения не указано» | В паспорте нет `pass.acquisition_time` | Это честное состояние, не заменять время на mtime без подписи |
| Дубликат после переименования | Имя входит в хеш входа | Сохранять устойчивую схему именования; не ожидать глобальной дедупликации |
| Старый пролёт в начале ленты | Выполнен новый пересчёт | Лента сортируется по публикации, не наблюдению |
| Число карточек ограничено, диск растёт | `max_items`, размеры `archive/public/work` | Лимит ленты не ротация; нужна отдельная согласованная политика хранения |
| После смены движка нет пересчёта | Прежний `processing_revision` | Увеличить версию рецепта, перезапустить воркер, оценить очередь |
| Не запускается после смены data_dir | Пути JSON и systemd расходятся | Переносить данные как отдельную операцию, не менять один ключ |
| SSH-деплой не видит станцию | Маршрут от runner, SSH, host key, sudo | Настроить доверенный сетевой путь; не отключать StrictHostKeyChecking |
| Нет кнопки Run workflow | Workflow отсутствует в default branch | Использовать файл-заявку и push-маркер; см. сборку и выпуск |

## 3. Безопасно повторить задание

```bash
sudo satdump-station status
sudo satdump-station retry --job ПОЛНЫЙ_64_СИМВОЛЬНЫЙ_ID
```

Вторую команду выполняйте после замены ID и исправления причины. Принимается только полный 64-символьный hex-ID и состояние `failed`; попытки сбрасываются. Нельзя использовать `retry` как произвольную команду пересчёта `done` или `superseded`.

Для новой научной версии измените рецепт/`processing_revision`. Не удаляйте запись вручную из SQLite: это нарушает договор с существующими публикациями.

## 4. Частые вопросы

<details>
<summary>Почему нельзя просто скормить папку PNG и получить любой цветосинтез?</summary>

Готовый PNG содержит уже визуализированное изображение. Штатный пересчёт требует каналов и метаданных `product.cbor` либо записи с корректным декодером. Сайт не восстанавливает утраченные измерения из цветов.

</details>

<details>
<summary>Почему нужны .ready и ожидание стабильности одновременно?</summary>

Маркер — обещание производителя о завершении передачи. Стабильность — дополнительная проверка. Без маркера паузу сети нельзя надёжно отличить от окончания копирования. Даже с маркером производитель не должен продолжать запись в уже объявленный готовым набор.

</details>

<details>
<summary>Можно ли запустить once и считать код 0 доказательством обработки всего архива?</summary>

Нет. `once` выполняет первоначальное обнаружение, ждёт окно стабильности и делает один цикл с максимум одним заданием. Ошибки задания сохраняются в очереди; сам процесс может завершиться с кодом 0. Проверяйте `status` и публикацию.

</details>

<details>
<summary>Почему каталог как будто пуст после отключения сетевого диска?</summary>

После размонтирования может остаться пустой локальный каталог. Текущий воркер не проверяет, что он является ожидаемым mountpoint. Нужны системный контроль монтирования и права. Ошибки обхода вложенных каталогов также не гарантированно попадают в сводку источников.

</details>

<details>
<summary>Почему north_up включён, но север сверху не подтверждён?</summary>

Настройка задаёт запрос. Подтверждение зависит от геолокации и записывается отдельно в JSON. При недостатке данных ориентация может сохраняться без утверждения о её проверенности.

</details>

<details>
<summary>Можно ли вынести SQLite на сетевой диск или запустить несколько воркеров?</summary>

Текущая архитектура рассчитана на локальную очередь и одного потребителя, защищённого flock. Распределённая очередь не реализована. Сетевым может быть вход, а не произвольно всё рабочее хранилище.

</details>

<details>
<summary>Почему rollback не вернул прежние настройки и изображения?</summary>

Откат переключает код. Конфигурация и данные живут отдельно и сохраняются. Историческое состояние восстанавливают из резервной копии по отдельному плану.

</details>

## 5. Известные границы, а не обещанные возможности

Нет автоматической ротации архива, распределённых воркеров, календарного диапазона в интерфейсе, автоматической настройки TLS, браузерной административной панели, автоматического определения произвольного IQ-формата или абсолютного контроля всех сетевых отказов. Тесты native-адаптера частично подменяют вызов движка; проверка JavaScript проверяет синтаксис, не внешний вид.

Успешный запуск в Stretch подтверждает отдельный базис среды, но не политики мандатного доступа, драйверы, ядро, графику и сетевые диски вашей Astra. [Текущий снимок состояния выпуска](../RELEASES.md).

## 6. Как оформить полезный отчёт об ошибке

Приложите версию Astra, архитектуру, SHA пакета, этап ошибки, ID задания, обезличенный конфиг, соответствующий фрагмент журнала и ожидаемый результат. Укажите, был ли это PNG, набор каналов или IQ, и воспроизводится ли ошибка при обычном SatDump той же версии.

Удалите SSH-ключи, пароли, токены, внутренние адреса и закрытые сведения. Контрольную запись публикуйте только при наличии разрешения. [Порядок участия](../../../CONTRIBUTING.md).
