# Установка и API Station / BOARD

[Руководство](README.md) · [Конфигурация](CONFIGURATION.md) · [UTC и планировщик](UTC_AND_SCHEDULER.md)

## Состав

Station включает обработчик файловой очереди, встроенную галерею, публичный каталог изображений и отдельный авторизованный API настроек. Публикуются полные и компактные PNG с JSON-паспортами; научные данные остаются в приватном архиве. Встроенная страница открывается без дополнительного проекта сайта.

## Установка

Из распакованного бинарного Station-пакета:

```bash
sudo ./install.sh
```

Мастер задаёт каталог данных, IPv4-адрес, порт, вариант сервера и источник. Enter принимает значение, `b` возвращает назад, `q` отменяет. Для установки без вопросов доступны `--yes` и `--non-interactive`; для отключения оформления терминала — `--no-color` и `--no-animation`.

Внешний источник и доступ из доверенной сети задаются явно:

```bash
sudo ./install.sh --non-interactive --listen 0.0.0.0 --port 8090 \
  --source-path /mnt/receiver/presentation --source-kind image
```

Источник мастера требует маркер готовности: `имя.png.ready` для изображения либо `.ready` внутри каталога продукта. Для сырой записи требуется источник `pipeline` с параметрами конкретного формата; он настраивается в центральной конфигурации, не подставляется вместо `image`.

Устанавливаются и включаются `satdump-worker`, `satdump-web`, `satdump-control`. Вариант `--web-server nginx` добавляет внутреннюю службу `satdump-board` и использует уже установленный nginx с отдельным конфигурационным файлом. Установщик не устанавливает nginx и не меняет системную glibc, NTP или политики Astra.

При ошибке активации восстанавливаются предыдущие код, настройки и службы. Данные и очередь этим откатом не восстанавливаются. `--no-start` предназначен для остановленной станции и пропускает проверку запуска.

```bash
sudo satdump-station doctor
satdump-station time-status
sudo satdump-station status
sudo satdump-station logs
```

`doctor` проверяет права от имени обработчика, конфигурацию, свободное место и наличие движка. Состояние синхронизации возвращается отдельно в `clock`. Работоспособность декодера проверяется контрольной записью, а не наличием исполняемого файла.

## Публичные маршруты

Галерея: `http://127.0.0.1:8090/`. Каталог: `GET /api/v1/board`. Применённая ревизия и фаза работы: `GET /api/v1/board/status`. Готовность по коду HTTP: `GET /health/ready`.

Встроенный сервер предназначен для localhost и доверенной ЛВС. Управление не становится доступным извне при изменении адреса публичного сервера.

## Управляющий API

Контракт: [board-openapi.json](../../../config/station/board-openapi.json). API слушает `127.0.0.1:8091`. Запросы требуют заголовок `Authorization: Bearer …`; токен хранится в `/etc/satdump-station/control.token`. Он не передаётся в URL или публичных файлах сайта. Для удалённого доступа используется SSH-туннель либо отдельно настроенный защищённый прокси.

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/control/health` | Состояние API |
| GET | `/api/v1/control/config` | Настройки и ETag |
| GET | `/api/v1/control/capabilities` | Приборы, пресеты и доступные настройки установленного движка |
| POST | `/api/v1/control/validate` | Проверка изменений без сохранения |
| PUT | `/api/v1/control/config` | Сохранение с `If-Match` |

Порядок изменения: прочитать настройки и ревизию → изменить `settings` → проверить → сохранить с прежним ETag → дождаться нужного `applied_revision`. HTTP 202 означает сохранение; применение происходит между заданиями. При HTTP 412 настройки перечитываются. Изменение рецепта требует `confirm_reprocess: true`, поскольку может вызвать пересчёт доступных исходных файлов.

Настраиваются источники и их пути, типы входов, маски, готовность файлов, интервалы очереди, лимиты, продукты, подписи и фильтры каталога. Источники находятся в `settings.station.sources`; сохранённый документ `data/control/active.json` имеет приоритет над базовым `station.json`.

Разрешённые корни и конвейеры задаёт администратор в `control-policy.json`. API отклоняет произвольные команды, исполняемые пути, Lua и параметры вне разрешённого перечня. Общий `data_dir`, службы, сеть и системные часы через API не изменяются.

Фильтры каталога не вызывают пересчёт. Они не удаляют опубликованные файлы и не ограничивают доступ по ранее известному URL.

В `settings.station.sources` поддерживается `required_instruments`. Качество набора находится в `processing_quality` карточки, а не в исходном паспорте; состояние последнего задания — в `/health.json` → `last_result`. Встроенная галерея поясняет их в локальной справке. [Контроль продукции](MTVZA_PROCESSING.md) · [Контракты](REFERENCE.md).

## Дополнительный интерфейс

Вместо встроенной галереи можно подключить свой каталог с `index.html`:

```bash
sudo satdump-station ui-deploy /path/to/board-files
```

Файлы копируются в отдельную версию; указатель `/opt/satdump-station/board-ui/current` переключается атомарно. Перезапуск веб-службы не требуется. Символьные ссылки и специальные файлы отклоняются. API и приватные маршруты не заменяются статическими файлами.

JavaScript, стили, изображения и шрифты должны быть локальными. CSP запрещает внешние CDN и сценарии внутри HTML. Node.js и npm на станции не нужны.

## Проверка выпуска

Программные тесты проверяют очередь, обе формы публикации, UTC, HTTP-маршруты, авторизацию, ревизии настроек, мастер установки и формирование служб. Испытание полного пакета дополнительно проверяет установку без интернета, действующий systemd, права, nginx, откат, контрольную радиозапись и перезагрузку на целевой Astra. [Порядок выпуска](BUILD_RELEASE.md).
