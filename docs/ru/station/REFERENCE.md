## 1. Команды station.sh / satdump-station

В исходниках и распакованном пакете используется `./station.sh`. После установки `/usr/local/bin/satdump-station` указывает на актуальную версию. Корневой `build.sh` — отдельный прежний сборщик движка.

| Команда | Где применять | Результат / оговорки |
|---|---|---|
| `help` | Везде | Справка без изменения системы |
| `build [--jobs N]` | Исходники | Полный пакет станции; нужны сборочные инструменты |
| `pack --engine DIR --runtime DIR --output DIR --revision SHA` | Подготовленная сборочная среда | Упаковка существующих компонентов |
| `test` | Исходники или пакет | Контрактные unittest; в пакете используется встроенный Python |
| `install [параметры]` | Бинарный пакет | Установщик; обычный запуск требует root |
| `deploy ARCHIVE USER@HOST` | Машина с SSH-маршрутом | Передача и вызов целевого установщика |
| `worker --config FILE` | Через systemd; вручную на отдельном стенде | Постоянное наблюдение и обработка |
| `once --config FILE` | При остановленном основном воркере | Один цикл, максимум одно задание; не осушение всей очереди |
| `serve --public DIR --host IPv4 --port N` | Обычно через systemd | Read-only сайт |
| `check --config FILE` | Станция | Конфиг станции, Python/Pillow, запуск `satdump version` |
| `status --config FILE` | Станция | Последние 30 заданий: ID, состояние, попытки, ошибка |
| `retry --job ID --config FILE` | Станция | Только `failed` → `pending`, сброс попыток |
| `logs` | Станция | `journalctl` для двух служб, последние 100 строк и наблюдение |
| `restart` | Станция | Перезапуск двух служб, перечитывание настроек |
| `rollback` | Станция | Предыдущий код, не откат данных |

`status/retry`, вызванные через `sudo satdump-station`, передают работу служебному пользователю, чтобы root не менял владельцев рабочих SQLite-файлов. Не запускайте второй `worker` поверх systemd-процесса: блокировка должна это запретить.

### Прямые Python-параметры

| Параметр | По умолчанию | Применение |
|---|---|---|
| `--config` | `/etc/satdump-station/station.json` | Команды очереди и проверки |
| `--public` | `/var/lib/satdump-station/public` | `serve` |
| `--host` | `127.0.0.1` | `serve` |
| `--port` | `8090` | `serve`; в CLI разрешён 1..65535, установщик ограничивает 1024..65535 |
| `--job` | пустая строка | `retry`, полный hex-ID |

Не все глобально принимаемые argparse-параметры используются каждой командой. Например, `--config` не задаёт веб-серверу каталог публикации вместо `--public`.

## 2. Параметры install.sh

| Параметр | Действие |
|---|---|
| `--data-dir /absolute/path` | Каталог данных при первой установке; существующие данные не мигрирует |
| `--listen IPv4` | Адрес сайта, по умолчанию localhost |
| `--port N` | Порт 1024..65535 |
| `--dry-run` | План, не полный тест пакета и запуска |
| `--no-start` | Размещение без обычного запуска/health-check |
| `--rollback` | Вернуть предыдущую версию кода |
| `--allow-compatible` | Обойти проверку имени Astra только на испытательном стенде |
| `--help` | Справка |

Инсталлятор не принимает произвольный `--prefix`: пути кода и активной конфигурации фиксированы. Не существует реализованной команды `uninstall` или автоматической миграции каталога данных.

## 3. Состояния и коды

| Состояние задания | Значение |
|---|---|
| `pending` | Ожидает обработки или следующей попытки |
| `running` | Текущая попытка |
| `done` | Материалы опубликованы |
| `failed` | Обычные попытки исчерпаны |
| `superseded` | Вход изменился; прежний снимок состояния больше не актуален |

`reprocess` возвращает 2 при неправильном количестве аргументов, 1 при перехваченной ошибке и 0 при штатном завершении. Воркер дополнительно проверяет выходные PNG/JSON. У `once` код 0 сам по себе не означает `done`: ошибки задания учитываются в SQLite. `/health.json` может отдавать 200 с неработающим воркером — проверяется содержимое.

## 4. Машинно-читаемые форматы

| Схема / файл | Назначение |
|---|---|
| `satdump.station/1` | Конфигурация станции |
| `satdump.gallery/1` | Каталог браузерной галереи |
| `satdump.presentation/1` и `/2` | Принимаемые JSON-паспорта; renderer этой ветки выпускает `/2` |
| `satdump.station.package/1` | Манифест бинарного пакета |
| `SHA256SUMS` | Контрольные суммы файлов внутри пакета |
| `*.tar.gz.sha256` | Сумма внешнего архива |
| `worker.json` | Обезличенный статус воркера; отдельного поля schema сейчас нет |

У карточки каталога есть `id`, `source`, `satellite`, `instrument`, `title`, `acquisition_time`, `file_mtime`, `published_at`, `width`, `height`, `native_presentation`, `preview`, `thumbnail`, `original`, `metadata`. Поле `native_presentation` определяется распознанным форматом паспорта, не криптографической аттестацией.

`catalog.total` — общее число найденных карточек; `items` может быть короче из-за `max_items`. `updated_at` относится к формированию каталога. URL элементов указывает на опубликованный набор, а не на произвольный путь файловой системы.

## 5. Словарь

| Термин | Значение в этом проекте |
|---|---|
| Station | Движок + окружение + воркер + сайт + установщик |
| Engine / движок | Сам SatDump, CLI/плагины/ресурсы |
| Runtime / среда исполнения | Python/Pillow и несистемные библиотеки отдельного комплекта |
| Launcher | Скрипт, который задаёт пути ресурсов/библиотек перед запуском бинарника |
| Pipeline / конвейер | Штатная последовательность декодирования SatDump |
| Product / продукт | Сохранённые данные прибора, обычно с `product.cbor` |
| Composite / цветосинтез | Продукт из каналов, выражений, LUT или алгоритма |
| Sidecar / паспорт | JSON рядом с изображением, описывающий его |
| Ready marker | Файл-договор о завершённости входа |
| Heartbeat | Периодическая запись, показывающая, что воркер продвигается |
| ABI / glibc baseline | Требования исполняемого кода к системной библиотеке; не сертификат ОС |
| Artifact / артефакт CI | Файл конкретного запуска Actions, не обязательно опубликованный релиз |
| Prerelease | Предварительный выпуск с явно указанными ограничениями |
| Atomic / атомарно | Смена видимого состояния целиком, без промежуточного набора |
| Idempotent / идемпотентно | Повтор действия не создаёт дополнительный результат при тех же условиях |
