# Атомарная публикация между файловыми системами

## Причина исправления

В системной приёмке run `34354343135` (коммит `877013dae42e36dca4bce5c0fa833730b166db05`) установка WEB/API и авторизация прошли, но обработчик получил `EXDEV` при переносе из `work` в `archive`. systemd изолирует разрешённые для записи каталоги отдельными bind-mount: обычный `rename()` между ними может не работать даже на одном физическом диске. Аналогичная граница существует между `work` и `public`.

## Реализация

Общий `move_tree` в `services/station/station.py` применяется и базовой очередью, и BOARD. Сначала используется обычное переименование. Только при `EXDEV` выполняется копирование в скрытый временный каталог на стороне назначения, синхронизация скопированных файлов и финальное переименование готового дерева в целевой каталог. Ошибки доступа не маскируются повторным копированием.

До финального переименования читатель не видит частичную публикацию: промежуточный `item.json` находится дополнительным уровнем глубже, чем область поиска каталога. При обычном исключении рабочий исходник сохраняется, незавершённая копия удаляется. После успеха удаляется только рабочая копия; входные данные приёмника не изменяются. При длительном копировании обновляется heartbeat и проверяется сигнал остановки. Существующая публикация не перезаписывается, символические ссылки и специальные файлы не переносятся.

Ограничения systemd и владельцы каталогов не ослаблены. Межфайловое копирование требует дополнительного места и операций ввода-вывода. Атомарная видимость не является полной гарантией сохранности всего задания при отказе диска или питания. После SIGKILL/потери питания может остаться скрытый `.transfer-*`; он не выдаётся за готовую продукцию и подлежит контролируемой очистке после проверки отсутствия активного задания.

## Проверка

`tests/station/test_cross_mount.py` содержит 11 регрессионных сценариев: настоящий перенос между `/tmp` и `/dev/shm` при наличии разных файловых систем, моделирование bind-mount, базовая и BOARD-очередь, неизменность PNG/JSON, отсутствие частичной выдачи, недостаток места, ошибка фиксации, отказ доступа, прерывание, ссылки/специальные файлы и защита существующей публикации. В окружении без отдельной файловой системы соответствующий тест явно пропускается.

Локальный полный набор: 81 тест прошёл на Python 3.5.3 из бинарного runtime. Выпуск всё равно допускается только после повторной проверки нового архива в независимом офлайн-окружении и с настоящим systemd. Этот документ не подтверждает физическую Astra, радиоприём или перезагрузку целевого компьютера.
