# 🚀 01 · Установка и первый запуск

[← Оглавление](README.md) · [Далее: архитектура →](DATAFLOW.md)

<a id="before"></a>
## 1. Что подготовить

| Требование | Зачем оно нужно | Проверка на целевой машине |
|---|---|---|
| Astra Linux **1.6**, x86_64 | Это целевой вариант установщика станции | `cat /etc/astra_version; uname -m` |
| Административный доступ | Создание пользователей, каталогов и служб | `sudo -v` |
| Bash, coreutils, util-linux, shadow/passwd, systemd | Штатные средства установки и запуска | `command -v bash sha256sum tar flock runuser systemctl` |
| Локальный каталог данных | SQLite и атомарные переименования не выносятся на SMB/NFS | `df -h /var/lib; findmnt /var/lib` |
| Проверенный **бинарный пакет станции** и `.sha256` | Установка не скачивает зависимости | [Выбор архива](../RELEASES.md) |

Размер запаса диска зависит от входов и количества продуктов. Значение `min_free_mb=2048` — порог остановки приёма новых заданий, **не оценка полного необходимого места**. Вход копируется, научные результаты и публикационные варианты занимают отдельное место.

> [!IMPORTANT]
> `Source code.zip`, пакет только движка и Desktop-релиз Astra 1.7 не подходят вместо полного `astra16-station`. Если нужный бинарный релиз ещё не опубликован, переходите к [сборке](BUILD_RELEASE.md), а не запускайте исходный установщик в надежде, что он скачает движок.

<a id="install"></a>
## 2. Проверить и распаковать пакет

**Где:** целевая Astra, каталог с доверенным архивом. Замените только значение `ARCHIVE` на реальное имя файла.

```bash
ARCHIVE='satdump-1.2.2-astra16-station-ВАШ_COMMIT-x86_64.tar.gz'
test -f "$ARCHIVE" && test -f "$ARCHIVE.sha256"
sha256sum -c "$ARCHIVE.sha256"
tar -xzf "$ARCHIVE"
cd "${ARCHIVE%.tar.gz}"
./station.sh help
```

Ожидается `OK` для выбранного архива. При несовпадении суммы **не устанавливайте** его. SHA-256 подтверждает целостность, но не доверие к неизвестному отправителю: архив и сумма должны происходить из проверенного релиза или контролируемой сборки.

Внутри должны находиться `engine/satdump`, `runtime/python`, `install.sh`, `station.sh`, `PACKAGE-MANIFEST.json`, `SHA256SUMS` и инструкции. Установщик дополнительно проверяет внутренний перечень файлов.

## 3. Выбрать режим установки

| Сценарий | Команда из корня пакета |
|---|---|
| Обычная станция; сайт только локально | `sudo ./install.sh` |
| Сайт в доверенной ЛВС | `sudo ./install.sh --listen 0.0.0.0 --port 8090` |
| Данные на отдельном локальном диске, первая установка | `sudo ./install.sh --data-dir /data/satdump-station` |
| Показать план без изменения системы | `./install.sh --dry-run` |
| Разместить код и конфигурацию без запуска | `sudo ./install.sh --no-start` |

`--dry-run` не проверяет весь бинарный комплект, реальное открытие порта и будущий запуск служб. `--no-start` **не выполняет** обычную проверку работоспособности. Это не режим безопасного горячего обновления: активный указатель кода всё равно переключается; на работающей станции сначала остановите службы.

При обычной установке создаются пользователи `satdump-station` и `satdump-web`, каталоги данных, конфигурация, службы и ссылка `/usr/local/bin/satdump-station`. Код размещается в версионном каталоге; `current` переключается после предварительных проверок. Затем установщик проверяет службы и `/health.json`.

> [!WARNING]
> Параметр `--allow-compatible` предназначен для испытательного Debian-стенда. Он отключает проверку названия ОС, **не превращает** Debian в Astra и не доказывает совместимость произвольной системы.

## 4. Проверить запуск

**Где:** установленная станция.

```bash
sudo systemctl is-active satdump-worker.service satdump-web.service
sudo systemctl status satdump-worker.service satdump-web.service --no-pager
sudo satdump-station status
```

В браузере станции откройте `http://127.0.0.1:8090/`. Пустая галерея при первом запуске — нормальное состояние. Для проверки HTTP без установки дополнительных программ:

```bash
/opt/satdump-station/current/runtime/python - <<'PY'
import json
from urllib.request import urlopen
with urlopen('http://127.0.0.1:8090/health.json', timeout=5) as response:
    status = json.loads(response.read().decode('utf-8'))
print(json.dumps(status, ensure_ascii=False, indent=2))
assert status.get('web_alive') and status.get('worker_alive')
PY
```

При нестандартных адресе и порте замените URL на значения из `/etc/satdump-station/web.env`. Состояние `worker_alive=true` означает свежий сигнал жизнеспособности, а не отсутствие ошибок декодирования. Проверяйте также `queue.failed` и `sources`.

## 5. Подать первый контрольный снимок

Возьмите известный PNG; тестовый снимок не должен содержать закрытые данные. Замените `/путь/контрольный.png`.

```bash
INBOX='/var/lib/satdump-station/inbox/images'
sudo install -o satdump-station -g satdump-station -m 0640 \
  '/путь/контрольный.png' "$INBOX/control.png.part"
sudo -u satdump-station mv "$INBOX/control.png.part" "$INBOX/control.png"
```

В стандартной конфигурации воркер проверяет папку каждые 10 секунд и ждёт 30 секунд неизменности файлов. Это параметры опроса, **не гарантированный срок готовности**: в очереди могут быть другие задания. В галерее должна появиться карточка, а в `status` — `done`. Отсутствие времени наблюдения у PNG без паспорта не является ошибкой.

Для цветосинтеза затем подайте контрольный набор каналов с `product.cbor` и `.ready`: [точная структура](INPUTS.md#products). Успешный PNG проверяет публикацию, но ещё не проверяет научную обработку.

## 6. Подключить источник приёмника

Редактируется **активный** файл `/etc/satdump-station/station.json`, не пример в исходниках. Сетевую папку сначала монтирует администратор. Учётной записи `satdump-station` нужны чтение файлов и проход по всем родительским каталогам.

```bash
sudo -u satdump-station test -r /mnt/receiver/control.png
sudo -u satdump-station test -x /mnt/receiver
sudo satdump-station restart
```

Отсутствие вывода `test` при коде 0 означает успех. Права на новые файлы должен обеспечивать процесс-производитель. Не выдавайте всем пользователям `chmod -R 777`.

## 7. После перезагрузки и обновления

Повторите проверку служб, откройте прежнюю карточку и подайте новый контрольный файл. После аварии очередь должна продолжить обработку; уже опубликованные материалы должны остаться доступны. Для обновления, резервной копии и отката используйте [эксплуатационное руководство](OPERATIONS.md), а не удаление `/opt` или базы вручную.
