# Спутниковый экран «Орбита» и управление Station

Ветка `release/1.2.2`. Спутниковая часть из предоставленных `Архив.tar.gz`
и `application.zip` встроена в `services/station/web/sat` и адаптер `satellite.py`.
Компоновка, таймлайн, два буфера проигрывателя, пиктограммы и ambient перенесены из
исходного спутникового интерфейса. PHP-приложение, посторонние метеостраницы,
демонстрационные наблюдения, пароли, зависимости сайта и шрифты не импортированы.
Шрифты системные; декоративные изображения оптимизированы в WebP. Это не
уменьшение генерируемых метеорологических изображений.

## Единственный источник истины

```text
SatDump + processing.json → PNG/JPEG и JSON-паспорт
  → существующий Worker: проверка файла, фактические размеры, публикация
  → оригинал + отдельное превью + малый предварительно размытый ambient
  → satellite.json → /api/v1/satellite/manifest → проигрыватель
```

По умолчанию `board.display.imageMode` равен `original`: браузер получает точный
файл публикации без уменьшения. Для слабого экрана администратор может выбрать
`preview`: сервер явно выдаёт свой вариант и его фактические размеры. Это
**режим конфигурации сервера**, а не эвристика браузера по разрешению монитора.

`image`, `originalImage`, `previewImage` и `ambientImage` имеют раздельные URL,
ширину и высоту. Основной файл и паспорт сохраняются побайтно. Размер из
`passport.output` сверяется с файлом: несовпадение становится предупреждением,
а не скрытием изображения. Ограничение декомпрессии `max_image_pixels` остаётся
на бэкенде. Небезопасные URL, ошибки загрузки и нарушения авторизации по-прежнему
отклоняются: это не проверки разрешения.

В JavaScript нет ограничений 1920×1080, минимального размера, отбраковки 4K и
клиентского повторного отбора по времени. Браузер сохраняет порядок манифеста,
декодирует два кадра и подгоняет изображение к сцене через `object-fit: contain`.
Вертикальный обзор можно выключить: тогда виден кадр целиком. При включённом
обзоре верх, середина и низ показываются по очереди; при изменении размера окна
смещения пересчитываются. Режим уменьшенной анимации учитывается.

## Время и содержимое паспорта

UTC берётся из явных полей времени или штатной UTC-подписи Presentation. Имя
файла и mtime не объявляются временем наблюдения. Снимок без времени остаётся
доступным, получает подпись «Время наблюдения не указано» и кнопку «Без времени»;
фиктивная отметка на таймлайне не создаётся. Сервер ограничивает историю по
съёмке, а для недатированных материалов — по давности публикации. Часы экрана
синхронизируются по HTTP Date, но не меняют состав выданной сервером очереди.

Показываются название, описание и назначение из паспорта, все примечания,
состав каналов и слоёв, формулы, диапазоны, физические величины и единицы,
качество и подтверждённая/неподтверждённая ориентация. Сохраняются исходные
формулировки, включая английские: браузер не заменяет их своим словарём и не
объявляет яркостную температуру восстановленной температурой облачной вершины.
Отсутствующие сведения честно обозначаются; факты не выдумываются.

Нативные `legend.color_stops`/`ticks`, `categories` и `components` отображаются
раздельно. RGB не получает фиктивную физическую шкалу. Для дополнительных
объяснений используется серверная настройка `presentation.legend.notes`;
она попадёт в паспорт новых продуктов. У готового внешнего паспорта доступны
также `product.description`, `product.purpose`, `layers`, `pass.details`.

Предоставленный набор содержит иллюстрации семейств Метеор-М, MetOp, NOAA/POES,
Арктика-М и Электро-Л. Для других аппаратов сохраняется их точное имя и выводится
условная универсальная пиктограмма, а не изображение другого спутника.

## Развёртывание

В полном **Station-пакете**, собранном командой `station.sh pack`/`build`, экран,
API, конфигурация и инструкции устанавливаются автоматически. Исходный архив
WEB-компонента из CI не содержит нативный движок и не является полной бинарной
поставкой. Для сборки пакета действуют прежние требования к переносимому движку
и Python/Pillow; новая установка не подменяет libc или компоненты ОС.

На Astra 1.6/1.7 используется установленный пакет ОС `apache2`. Если пакет
отсутствует, установщик сообщает об этом до переключения версии: администратор
устанавливает Apache из разрешённого репозитория/носителя своей ОС. Глобальные
сайты Apache, его конфигурация и системная служба не изменяются.

```bash
# Выполнять из распакованного полного Station-пакета, не WEB-компонента.
sudo ./install.sh --interactive
# Доступ с экрана в доверенной локальной сети:
sudo ./install.sh --yes --web-server apache2 --listen 0.0.0.0 --port 8090
sudo systemctl status satdump-worker satdump-control satdump-board satdump-web
```

Сайт: `http://IP_СТАНЦИИ:8090/`. Локально: `http://127.0.0.1:8090/`.
Публичный порт не даёт доступа к управлению. По умолчанию без `--listen` сайт
слушает только `127.0.0.1`; это безопасный исходный режим. Для доступа из ЛВС
также должен быть разрешён выбранный TCP-порт межсетевым экраном станции.

Настройки: `http://127.0.0.1:8093/settings/`. С удалённого рабочего места:

```bash
ssh -L 8093:127.0.0.1:8093 USER@STATION
# Открыть http://127.0.0.1:8093/settings/ на рабочем месте.
```

Администратор читает токен локально из `/etc/satdump-station/control.token`.
Токен вводится в форму, живёт только в памяти вкладки и не сохраняется в URL,
localStorage или sessionStorage. Не публикуйте этот токен. Удалённое управление
через незашифрованный публичный HTTP запрещено; используйте SSH или отдельно
настроенный TLS. Host и Origin проверяются сервером.

В форме доступны показ/тайминг/ambient/режим файла, видимость продукции,
источники в разрешённых каталогах, параметры очереди и оформления, пресеты и
выражения каналов установленного движка. Root-политика, пути исполняемых файлов,
Lua, shell и произвольные аргументы не становятся редактируемыми через сайт.

Порядок: загрузить → изменить → проверить → сохранить. `If-Match` защищает от
потери чужих изменений (412). Изменения рецептов/источников требуют отдельного
подтверждения повторной обработки (409). Ответ 202 означает сохранение;
«Применено обработчиком» показывается только по свежему heartbeat фактической
ревизии. Изменения показа не запускают декодирование повторно.

OpenAPI доступен локально по `/api/v1/openapi.json`, исходник —
`config/station/board-openapi.json`. Основные методы:
`/api/v1/satellite/manifest`, `/api/v1/satellite/config`, `/api/v1/board`,
`/api/v1/control/config`, `/validate`, `/capabilities`, `/status`.
Манифест поддерживает GET/HEAD и ETag/304, обновления не обрывают текущий кадр.
Смена файла оригинал/превью применяется даже во время паузы.

## Проверки и границы приёмки

```bash
./station.sh test
node --test services/station/web/sat/js/player.test.mjs
python3 -m unittest discover -s tests/contracts -v
python3 -m openapi_spec_validator config/station/board-openapi.json
python3 tests/browser/satellite_smoke.py --server apache2
python3 tests/browser/satellite_smoke.py --server nginx
# Без браузера: реальный HTTP-прокси, авторизация, кадры, паспорт и OpenAPI.
python3 tests/browser/satellite_smoke.py --server apache2 --http-only
```

Дополнительные зависимости нужны только разработчику/CI, не станции:
Playwright и его Chromium, jsonschema, openapi-spec-validator. Проверки не
отключают ошибки и не изменяют браузерные политики среды. В CI используются
изолированные браузеры на стандартных runners.

`Satellite WEB` проверяет всю HTTP-цепочку, реальные PNG разных пропорций и
размеров, загрузку/декодирование/автосмену, синхронный видимый фон, таймлайн,
легенды, локальные ресурсы, формы, применение ревизий и мобильную форму настроек.
Отдельно запускается официальный Astra UBI 1.7.5 с пакетами ОС. Прежняя проверка
Station на Debian Stretch выполняет реальные Python 3.5/Pillow тесты, но не
заменяет приёмку полной Astra 1.6. `Build All` запускается при изменениях
нативного кода; WEB-изменения не занимают посторонние Android/ARM runners.

Браузерные иллюстрации в тестах синтетические и проверяют отображение, не
метеорологическую достоверность тестовых пикселей. Эти тесты не являются
радиоприёмом, проверкой оборудования или полной загрузкой ОС с systemd.
Результаты конкретного запуска и снимки экрана находятся в артефактах CI.
