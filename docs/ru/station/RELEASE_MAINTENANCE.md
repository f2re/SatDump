# Исправления первого запуска Station / BOARD

9 сентября 2026 года. Целевая ветка: `release/1.2.2`.

## Исправления

Проверка среды от имени обработчика использует уже установленную проверенную копию `/opt/satdump-station/releases/<версия>/runtime/python`. Распакованный архив может лежать в закрытом домашнем каталоге; выдавать служебным пользователям доступ к нему не требуется.

Проверка `nginx -t` запускается от `satdump-web`, как сама служба. nginx создаёт PID и временные файлы даже при проверке конфигурации; запуск проверки от root оставлял файлы с несовместимыми правами и приводил к отказу первого непривилегированного старта.

Четыре регрессионных теста в `tests/station/test_install_permissions.py` проверяют закрытый каталог, выбор runtime, соответствие пользователя unit-файлу и фактический первый запуск nginx без исправления владельцев и без автоматического рестарта. Привилегированные тесты изменяют только временные каталоги и не создают пользователей или службы. При отсутствии прав или nginx соответствующие интеграционные тесты явно пропускаются; полный systemd acceptance выполняет реальные службы отдельно.

## Единая цепочка выпуска

Сохраняется существующий `.github/workflows/station-astra16.yml`. Повторное использование компонентов реализовано в `scripts/station/reuse-components.py`, а не отдельным конкурирующим релизным сценарием.

Полная сборка ревизии `d7eff18016debaeb5719161d89b218fbbae4b1c7` в run `34349962244` создала glibc224-пакет и прошла офлайн-проверку. Установочная приёмка старого пакета не прошла: он не выдаётся за готовый дистрибутив. Для нового пакета допускаются закреплённые SHA-256 компоненты только при неизменности входов нативной сборки. Исходная ревизия компонентов записана отдельно в `component_provenance` манифеста, а `git_commit` относится к исходникам Station этого выпуска.

Новый архив заново проходит проверки Python 3.5 без сети и полный systemd-сценарий: WEB/API, публикация PNG и паспорта, права пользователей, повторная установка, nginx, откат, занятый порт, восстановление настроек и возобновление очереди. Публикация зависит от результата этой приёмки; существующие релизы не заменяются.

Приёмка на одноразовой Ubuntu VM с настоящим systemd не заменяет проверку физической Astra 1.6, её мандатного доступа, радиозаписи и перезагрузки. Выпуск является предварительным инженерным. Astra 1.5 не объявляется поддерживаемой; на пользовательский узел ничего не развёртывается.
