# Исправление установщика и выпуск Station / BOARD

9 сентября 2026 года. Целевая ветка: `release/1.2.2`; default branch не изменяется.

## Исправления

Проверка среды от имени обработчика теперь использует уже установленную проверенную копию `/opt/satdump-station/releases/<версия>/runtime/python`. Распакованный архив может лежать в закрытом домашнем каталоге; выдавать служебным пользователям доступ к нему больше не требуется.

Проверка `nginx -t` запускается от `satdump-web`, как сама служба. nginx создаёт PID и временные файлы даже при проверке конфигурации; запуск проверки от root оставлял файлы с несовместимыми правами и приводил к отказу первого старта.

Эти случаи проверяются `tests/station/test_install_permissions.py`: закрытый каталог, выбор runtime, соответствие пользователя unit-файлу, фактический первый запуск nginx без исправления владельцев и без автоматического рестарта. Привилегированные тесты изменяют только временные каталоги и не создают пользователей или службы.

## Повторное использование нативной сборки

Полная сборка исходной ревизии `d7eff18016debaeb5719161d89b218fbbae4b1c7` в run `34349962244` завершилась успешно и создала glibc224-пакет. Установочная приёмка этого старого пакета не прошла. Поэтому он не публикуется как готовый дистрибутив.

Для исправления только установщика не нужно повторно компилировать идентичный движок. `maintenance.py` проверяет исходную ревизию, её принадлежность истории, контрольные суммы пакета и полный список изменённых файлов. Разрешены только явно перечисленные установочные исправления, тесты, эта инструкция и сценарий выпуска. Изменение ядра, ресурсов, конфигурации приборов, Python runtime-сборщика или другого файла прекращает процедуру: требуется полная сборка.

В новом пакете `git_commit` — ревизия установочных исходников. `maintenance.engine_git_commit` и `maintenance.runtime_git_commit` — ревизия фактически скомпилированных компонентов. Их содержимое, режимы файлов и символьные ссылки не меняются; контрольные суммы деревьев сохранены в манифесте. Отдельный `STATION-BUILD-PROVENANCE.json` связывает прежнюю сборку, новую ревизию и SHA-256 нового архива.

## Условия публикации

`station-maintenance.yml` выполняется на pull request для проверки, но не публикует и не развёртывает ничего. Только push в `release/1.2.2` с маркером `[station-maintenance-release]` допускает выпуск. Правила проверки происхождения GitHub-артефакта, неизменности компонентов, тесты Python 3.5 без сети и полный systemd-сценарий установки обязательны. Публикуется ровно проверенный архив с `STATION-ACCEPTANCE.json`, без пересборки после приёмки и без замены существующих релизов.

Приёмка на одноразовой Ubuntu VM с настоящим systemd не заменяет проверку Astra 1.6, мандатного доступа, оборудования, радиозаписи и перезагрузки. Выпуск отмечается предварительным инженерным; Astra 1.5 не объявляется поддерживаемой. Автоматической установки на пользовательскую станцию в этой цепочке нет.
