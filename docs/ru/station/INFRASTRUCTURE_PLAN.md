# Station / BOARD — серверная инфраструктура

Базовая ревизия: `009907ec1c0735606fc316973f53eaf5b2c8e48f`, ветка `release/1.2.2`.
Дата: 9 сентября 2026 года.

## Граница этапа

Новый веб-интерфейс, HTML/CSS/JavaScript, макеты и оформление BOARD не входят в этот этап. Требуются инфраструктура публикации, API управления и понятное автоматическое развёртывание. Существующие научные алгоритмы SatDump и исходный паспорт presentation сохраняются.

Эта страница фиксирует ТЗ. Само её наличие не означает, что исполняемая реализация записана в эту ветку, собран бинарный пакет или выполнено развёртывание на Astra.

## Архитектура

Три обязательные службы: обработчик `satdump-worker`, сервис чтения продукции `satdump-web`, авторизованный локальный API `satdump-control`. Отдельные пользователи; WEB не читает очередь, входные записи и настройки. API не получает root и не выполняет команды ОС.

Поток: разрешённые входы -> очередь SQLite -> рабочая копия -> SatDump/presentation -> приватный научный архив + публичные PNG/JSON/превью -> каталог BOARD. Не выводить время наблюдения из mtime. Не выдавать запрос north_up за подтверждённую геолокацию. Полный и компактный варианты должны происходить из настоящего renderer, а не декоративной обрезки.

Основной автономный WEB-профиль сохраняет встроенный Python. Дополнительный nginx используется только из уже установленного пакета ОС, с собственными конфигурацией и unit-файлом, без изменения чужого /etc/nginx и системных библиотек. Управляющий API остаётся на loopback; проксирование в браузер допускается только через явно настроенный TLS. Публичная эксплуатация в интернете требует отдельной оценки безопасности.

Astra 1.6 x86_64 — целевой профиль glibc224 с обязательной фактической приёмкой. Astra 1.5 не объявляется поддерживаемой и не включается простым обходом проверки версии. Нужна отдельная сборка/проверка ABI. Современный Uvicorn требует Python 3.10+; добавление его в базовый Python 3.5 пакет не является совместимым вариантом.

## Установочный сценарий

Мастер: предыдущие или безопасные значения -> каталог данных -> адрес/порт WEB -> сервер -> вход/тип данных -> итоговый план -> явное подтверждение -> предварительные проверки -> установка -> запуск всех служб -> проверка связности.

Enter принимает значение, b возвращает назад, q отменяет. Ошибочный ввод запрашивается повторно. Цвет и индикатор активности только в терминале; NO_COLOR и отключение анимации; чистые журналы для CI. Не показывать выдуманные проценты/ETA. Не подавлять фактические коды ошибок. Восстанавливать курсор при сигнале.

Обновление сохраняет конфигурацию. Ошибка активации восстанавливает предыдущие код, настройки и службы. Данные и очередь не откатываются автоматически. no-start — только подготовительное размещение на остановленной станции. SSH передаёт параметры как данные, сохраняет строгую проверку ключа узла и проверяет архив до/после передачи.

## API будущего интерфейса

GET /api/v1/board: каталог изображений и ссылок на паспорта. GET /api/v1/board/status: фактически применённая обработчиком ревизия.

GET /api/v1/control/config: документ и ETag. GET /api/v1/control/capabilities: реальные приборы/пресеты установленного движка и перечень изменяемых полей. POST /api/v1/control/validate: проверка без записи. PUT /api/v1/control/config: атомарное сохранение с If-Match. Изменение рецепта требует явного подтверждения возможной массовой повторной обработки. Применение — между заданиями; 202 не означает немедленное принятие обработчиком.

Строгие типы, запрет NaN и повторных ключей, ограничение размера тела, проверка Host/Origin, токен не в URL. Не принимать Lua, исполняемые пути, произвольные argv, системные unit-файлы. Входные пути ограничиваются политикой root. Изменение общего data_dir требует отдельной контролируемой миграции, не простой записи из браузера.

Фильтры видимости BOARD не должны инициировать научный пересчёт. Скрытие карточки — не удаление файла и не разграничение доступа к уже опубликованному URL.

## Рабочие пакеты по ролям

Это распределение задач, не утверждение о запуске независимых агентов.

- Установка: Bash-мастер, SSH, обновление и восстановление; проверки терминала, сигналов, прав и повторной установки.
- API/безопасность: схемы, ревизии, токен, границы путей, nginx; проверки авторизации, CAS, обхода путей и ограничений записи.
- Продукция: адаптер реальных PNG/JSON в BOARD; проверка обоих вариантов и сохранения научных метаданных.
- Сборка/Astra: runtime, упаковка, настоящий systemd, установка без сети, обновление, откат, перезагрузка.
- Будущий интерфейс: использование capabilities/OpenAPI; оформление отдельным этапом без переноса полномочий root в браузер.
