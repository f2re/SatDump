# ⚙️ 04 · Полный справочник конфигурации

[← Источники](INPUTS.md) · [Оглавление](README.md) · [Продукты →](PRODUCTS.md)

## 1. Какие файлы редактировать

| Файл | Назначение | Когда читается |
|---|---|---|
| `/etc/satdump-station/station.json` | Источники, пути, очередь и лимиты | При запуске воркера |
| `/etc/satdump-station/processing.json` | Дополнения к настройкам SatDump | При запуске воркера; копия передаётся заданиям |
| `/etc/satdump-station/web.env` | Адрес и порт HTTP | При запуске веб-службы systemd |
| `config/station/*.json` в исходниках/пакете | Шаблоны первой установки | Не активные настройки станции |
| `/etc/satdump-station/*.example` | Образцы из обновлённого пакета | Автоматически не применяются |

> [!TIP]
> После изменения активных JSON выполните `sudo satdump-station restart`. Горячая перезагрузка конфигурации не реализована. Изменение `processing.json` меняет рецепт и может поставить весь доступный входной архив на повторную обработку.

## 2. Общие поля station.json

В таблице указаны значения **поставляемого примера**. Где программный fallback отличается, это отмечено отдельно. JSON не допускает комментарии, завершающие запятые и `True/False`: используются `true/false`.

| Поле | Тип / пример | Значение и ограничения |
|---|---|---|
| `schema` | строка `satdump.station/1` | Обязательная версия конфигурации |
| `title` | строка `Спутниковые наблюдения` | Заголовок каталога и сайта |
| `data_dir` | абсолютный путь `/var/lib/satdump-station` | Отдельное хранилище данных, не `/`, `/var` и другие общие системные каталоги |
| `engine` | абсолютный путь `/opt/satdump-station/current/engine/satdump` | Используйте launcher, не внутренний `bin/satdump`: launcher задаёт библиотеки и ресурсы |
| `processing_config` | строка `processing.json` | Имя файла относительно каталога `station.json` |
| `processing_revision` | строка `1` | Ручная версия рецепта; увеличьте для пересчёта после смены движка |
| `poll_seconds` | целое `10` | Пауза между незанятыми проходами; минимум 1 |
| `settle_seconds` | целое `30` | Окно неизменности входа; минимум 0, ноль предназначен прежде всего для тестов |
| `timeout_seconds` | целое `1800` | Тайм-аут одного native-вызова, не обязательно всего многоприборного пролёта; минимум 1 |
| `max_attempts` | целое `3` | Попытки обычного задания до `failed`; минимум 1 |
| `native_threads` | целое `2` | Передаётся как `OMP_NUM_THREADS`; не ограничивает все потоки всех библиотек |
| `min_free_mb` | целое `2048` | Резерв свободного места, в коде без поля fallback 1024; минимум 0 |
| `max_input_mb` | целое `32768` | Максимальный суммарный размер входного задания; минимум 1 |
| `max_log_mb` | целое `32` | Ограничение журнала одного вызова/задания; минимум 1 |
| `max_image_pixels` | целое `90000000` | Порог декомпрессии изображения; не лимит RAM процесса |
| `max_items` | целое `1000` | Максимальное число карточек в выдаваемом каталоге; минимум 1; старые файлы не удаляет |
| `keep_work` | boolean `false` | Сохранять рабочий каталог после успешной публикации; остатки неуспешных попыток требуют отдельного контроля |
| `archive_science` | boolean, по умолчанию `true` | В типовом JSON не указан; сохраняет приватный результат. Не выключайте без политики хранения |
| `sources` | массив объектов | Описания источников; см. ниже |

Параметры с `_mb` в коде умножаются на `1024²`, то есть фактически задают МиБ. Перед обработкой проверяется запас примерно `2 × размер входа + min_free_mb`. Это не прогноз точного размера всех композитов: выход может оказаться больше. Аппаратные квоты памяти/диска самим этим параметром не устанавливаются.

## 3. Описание каждого источника

| Поле | Обязательность / умолчание | Смысл |
|---|---|---|
| `id` | обязательно, уникально | Латинские буквы, цифры, `_`, `-`; используется в очереди и интерфейсе |
| `kind` | обязательно | `image`, `product` или `pipeline` |
| `path` | обязательно | Абсолютный доступный каталог |
| `enabled` | необязательно, `true` | `false` выключает обнаружение источника |
| `patterns` | для файловых входов | Массив масок; default PNG/JPEG. Для IQ/кадров задавайте явно |
| `require_ready` | по умолчанию `true` только для `product` | Проверять `.ready`/`имя.расширение.ready`; для pipeline задавайте явно |
| `satellite` | необязательно | Подпись источника, когда в паспорте нет соответствующего поля |
| `instrument` | необязательно | Аналогичный резервный текст прибора |
| `pipeline` | для включённого `pipeline` | Точный идентификатор конвейера SatDump |
| `input_level` | для включённого `pipeline` | Уровень входа, например `baseband`; зависит от конвейера |
| `options` | массив строк, по умолчанию `[]` | Аргументы процесса, не строка shell и не исполняемый код |

Каталог входа не должен пересекаться с `public`, `work`, `state`, `archive`, `logs`. Не настраивайте выход как вход: это создаёт цикл переработки. Избегайте перекрывающихся источников, даже если один из них временно выключен.

### Пример источника готовых изображений

Добавляется **как объект в массив `sources`**, а не вместо всего файла конфигурации:

```json
{
  "id": "receiver_images",
  "kind": "image",
  "enabled": true,
  "path": "/mnt/receiver/images",
  "patterns": ["*.png", "*.jpg", "*.jpeg"],
  "require_ready": true,
  "satellite": "Источник станции приёма"
}
```

Чтение `/mnt/receiver/images` и формирование маркеров заранее обеспечиваются отдельно. Значения `satellite/instrument` не выводятся автоматически из имени файла.

## 4. Дополнения к настройкам SatDump

Типовой `processing.json`:

```json
{
  "satdump_general": {
    "tle_update_interval": {"value": "Never"},
    "log_to_file": {"value": false},
    "presentation_enabled": {"value": true},
    "presentation": {
      "enabled": true,
      "save_presentation": true,
      "save_minimal": true,
      "save_legacy_alias": false,
      "north_up": true
    }
  }
}
```

| Настройка | Эффект |
|---|---|
| `presentation_enabled.value` | Общее включение презентационного контура |
| `save_presentation` | Полный вариант; именно его выбирает текущий воркер для сайта |
| `save_minimal` | Компактный вариант; остаётся в научном архиве |
| `save_legacy_alias` | Совместимый `_annotated.png`; в типовом профиле отключён для уменьшения дублей |
| `north_up` | Запрос ориентации, а не утверждение о проверенной геопривязке |
| `tle_update_interval`, `log_to_file` | Воркер дополнительно принудительно задаёт `Never` и `false` для своих заданий |

В native-команде применяется **JSON Merge Patch** к основной конфигурации SatDump. Вложенные объекты объединяются, а массивы заменяются целиком; `null` может удалить ключ. Не вставляйте полный чужой `satdump_cfg.json`, если требуется изменить один пресет.

Пресеты дополняются по пути `viewer.instruments.<instrument>.rgb_composites.<preset>`. Идентификаторы и названия берутся из реального `engine/share/satdump/satdump_cfg.json`. У конкретного композита могут быть собственные `presentation`/`autogen`, переопределяющие общие ожидания. Если отключить полный вывод для всех композитов, задания станции завершатся отсутствием публикационных PNG.

## 5. Адрес и порт сайта

`web.env` — простой файл данных, не сценарий shell:

```text
SATDUMP_HOST=127.0.0.1
SATDUMP_PORT=8090
```

Установщик поддерживает IPv4 и порт `1024..65535`. `0.0.0.0` означает все IPv4-интерфейсы, а не адрес, который нужно вводить на другом компьютере: в браузере клиента нужен IP станции. Не помещайте сюда команды, кавычки вокруг значений, `export` и секреты.

Чтобы изменить адрес с проверкой запуска, повторно запустите установщик **из установленного пакета**:

```bash
sudo /opt/satdump-station/current/install.sh --listen 0.0.0.0 --port 8090
```

Он сохраняет остальные настройки, если их не переопределяют явные параметры.

## 6. Проверка и безопасное изменение

```bash
sudo cp -a /etc/satdump-station/station.json /etc/satdump-station/station.json.backup
sudo /opt/satdump-station/current/runtime/python -m json.tool \
  /etc/satdump-station/station.json > /dev/null
sudo /opt/satdump-station/current/runtime/python -m json.tool \
  /etc/satdump-station/processing.json > /dev/null
sudo satdump-station check
sudo satdump-station restart
sudo satdump-station status
```

`json.tool` проверяет только синтаксис. `check` проверяет конфигурацию станции, Python/Pillow и запуск `satdump version`; это **не полная проверка пресетов, входных прав и геолокации**. Окончательная проверка — контрольное задание.

## 7. Что не происходит автоматически

Изменение `data_dir` после установки не переносит данные; установщик запрещает конфликт с сохранённым путём. Удаление источника из конфигурации не удаляет его старые задания. Смена `processing_revision` не удаляет предыдущие публикации. `max_items` не выполняет ротацию. Эти операции планируются отдельно: [эксплуатация](OPERATIONS.md).
