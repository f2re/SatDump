# 🎛️ 05 · Цветосинтез, геометрия и презентационный слой

[← Настройки](CONFIGURATION.md) · [Оглавление](README.md) · [Галерея →](WEBSITE.md)

## 1. Два разных результата

**Научный результат** хранит измерения, каналы и/или геопривязанный растр. **Презентационная копия** предназначена для чтения человеком: подписи, спутник, прибор, время, легенда и ограничения. Они не взаимозаменяемы.

```text
Запись / каналы
  → декодирование и калибровка
  → выражение RGB, LUT либо алгоритм SatDump
  → геометрическая коррекция и доступная проекция
  ├── научные результаты в archive/
  └── отдельный презентационный PNG + JSON
       → JPEG-превью и миниатюра → сайт
```

Плашки не добавляются внутрь геопривязанного GeoTIFF. Научные значения не восстанавливаются из JPEG-превью сайта. Оригинал на сайте — файл конкретной публикационной карточки, не весь набор измерений.

## 2. Кто выполняет операции

| Операция | Исполнитель |
|---|---|
| Проверка наличия необходимых каналов | SatDump |
| Калибровка и вычисление композита | SatDump |
| Выражения RGB, LUT, Lua/C++-алгоритмы | Реальный пресет движка |
| Геометрическая коррекция, проекция, наложения | SatDump при наличии достаточных данных |
| Плашки и машинно-читаемый паспорт | Presentation renderer SatDump |
| Масштабирование для просмотра | Pillow, только отдельные копии |
| Фильтрация и перелистывание | Браузер |

Воркер не подбирает научную палитру по внешнему виду изображения и не заменяет неподдерживаемый алгоритм декоративным RGB.

## 3. Повторная обработка сохранённых каналов

Команда работает в переданном каталоге продукта, поэтому вручную всегда используйте **копию**:

```text
engine/satdump reprocess COPIED_PRODUCT_DIRECTORY PROCESSING_JSON
```

Воркер создаёт такую копию сам. В ней отключается кеш автосинтеза для рабочего объекта; старые оформленные результаты убираются до пересчёта. TLE по сети команда не обновляет. Для геолокации нужны сохранённые сведения продукта и необходимые локальные ресурсы.

> [!IMPORTANT]
> Подтверждением задания служит новый `_annotated_presentation.png` с читаемым паспортом, а не только код возврата 0. Однако наличие одного PNG ещё не доказывает, что сформированы **все** ожидаемые приборы/композиты.

## 4. Полное и компактное оформление

| Файл | Значение | Текущая станция |
|---|---|---|
| `…_annotated_presentation.png` | Полное оформление | Основная карточка сайта |
| `…_annotated_presentation.json` | Паспорт полного варианта | Доступен по ссылке «Паспорт JSON» |
| `…_annotated_minimal.png` | Компактный вариант | Сохраняется в `archive`, не переключается отдельной кнопкой сайта |
| `…_annotated.png` | Совместимый прежний псевдоним | Обычно выключен, чтобы не плодить дубликаты |
| `…-preview.jpg` | Обзорная копия ≤1920×1080 | Большой просмотр в браузере |
| `…-thumb.jpg` | Миниатюра ≤480×270 | Лента карточек |

Масштабирование пропорциональное, без обрезки. Узкая полоса может оставаться узкой: сайт не растягивает её до условного «полного кадра». Прозрачность для JPEG-превью сводится на фон; оригинальный публикационный файл сохраняется отдельно.

## 5. Как интерпретировать паспорт

| Поле | Что читать |
|---|---|
| `schema` | Версия контракта; renderer этой ветки формирует `satdump.presentation/2` |
| `layout` | Макет, например `editorial` или `minimal` |
| `pass.satellite`, `pass.instrument`, `pass.product` | Источник, прибор, название продукта |
| `pass.acquisition_time` | Подпись времени наблюдения; не `mtime` файла |
| `orientation.north_up_requested` | Был ли запрошен север сверху |
| `orientation.north_up_verified` | Удалось ли подтвердить ориентацию |
| `orientation.description` | Объяснение выбранной/сохранённой ориентации |
| `legend.kind` | `continuous`, `categorical`, `composite` или `none` |
| `legend.components` | Компоненты RGB, каналы, спектральные диапазоны и формулы |
| `legend.notes` | Ограничения и предупреждения интерпретации |

`north_up_requested=true` и `north_up_verified=false` не противоречат друг другу: запрос был, достаточных данных для подтверждения не оказалось. Сайт не делает самостоятельную географическую проверку изображения.

## 6. Научные ограничения, которые нельзя скрывать оформлением

| Ошибочная подпись | Корректное действие |
|---|---|
| «Температура верхней границы облаков» для любой ИК-раскраски | Указать яркостную температуру, если выполнена только соответствующая калибровка; название восстановленного параметра требует отдельного алгоритма |
| «Тип облачности» у обычной температурной палитры | Не выдавать раскраску за классификацию |
| Числовая шкала для произвольного RGB | Показать компоненты/формулы и условность цветов |
| Время файла под видом времени наблюдения | Подписывать эти значения раздельно |
| «Север сверху» без достаточной геолокации | Сохранить честный статус проверки из паспорта |

Методические основания и возможности renderer: [семантика](../PRESENTATION_SEMANTICS.md), [принципы оформления](../PRESENTATION.md), [макеты](../PRESENTATION_LAYOUTS.md), [картография](../MAP_OVERLAYS.md).

## 7. Проверка нового пресета

Зафиксируйте контрольный набор, версию движка и `processing.json`. Убедитесь, что в нём есть требуемые каналы. Сравните обычный запуск SatDump и результат станции на одинаковом входе. Проверьте названия, UTC, направление пролёта, геометрию, легенду, единицы и отсутствие ложных физических утверждений. Затем проверьте читаемость полного изображения и уменьшенного превью.

После изменения пресета перезапустите воркер. После смены алгоритма/бинарного движка при прежнем JSON увеличьте `processing_revision`. Результат должен стать новой версией, а не молча заменить старую публикацию.
