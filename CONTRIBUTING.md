## Область работы

Эти правила относятся к ветке **`release/1.2.2`** форка `f2re/SatDump`. Сохраняйте совместимость действующих точек входа и не переносите исходные каталоги CMake только ради внешнего порядка. Новые пользовательские сценарии начинаются с понятной команды и документации.

## Перед изменением

| Что меняется | Что проверить |
|---|---|
| CLI / Bash | Справка, ошибки аргументов, права, повторный запуск, отсутствие скрытой загрузки при офлайн-установке |
| Воркер | Готовность входа, очереди после сбоя, неизменность оригинала, новые версии рецепта |
| Цветосинтез | Реальные каналы, калибровка, физический смысл, геолокация, PNG и JSON |
| Сайт | Пустой архив, отсутствие сети, длинные подписи, UTC, клавиатура, отсутствие XSS |
| Упаковка | Базис glibc, комплектность runtime, checksum, автономный запуск распакованного пакета |
| Документация | Ссылки, исполнимый синтаксис примеров, область команды и честные ограничения |

## Минимальные проверки

**Где:** корень исходного дерева. Для тестов станции нужен Pillow; установка сборочных зависимостей на этом этапе не относится к офлайн-установке на Astra.

```bash
python3 scripts/docs/check.py
python3 -m unittest discover -s tests/docs -v
./station.sh test
bash -n station.sh
bash -n install.sh
node --check services/station/web/app.js
```

Используйте Python с установленным Pillow для `station.sh test`. Команды `bash -n` и `node --check` проверяют синтаксис, не выполняют сценарий установки и не проверяют внешний вид интерфейса. Для runtime сохраняется совместимость с Python 3.5: не вводите f-строки, dataclass и более новые API без пересмотра целевого окружения. Проверяйте совместимость не только грамматики, но и вызываемых функций.

## Как описать изменение

В PR или коммите укажите задачу, изменённые пользовательские команды, результат проверок, ограничения и способ отката. Не называйте проверку в Debian приёмкой Astra. Если тест использует заглушку native-вызова, напишите это явно. Ошибки не скрываются под `continue-on-error` ради зелёной плашки.

Страницы с параметрами и неочевидным поведением обновляются вместе с кодом. Новый документ включается в [навигационный манифест](docs/navigation.json), оглавление и маршрут чтения. Старые ссылки по возможности сохраняются через страницы-переходы.

## Релизная дисциплина

`[station-release]` и `[station-deploy]` — действующие запросы, не декоративные слова коммита. Не добавляйте их в изменение документации без намерения собрать или установить пакет. Пользовательский запрос на оформление README сам по себе не разрешает неподготовленный SSH-деплой.

Изменение Markdown не переиздаёт существующие бинарники. Для выпуска используйте [порядок CI/CD](docs/ru/station/BUILD_RELEASE.md) и [шаблон release notes](docs/RELEASE_TEMPLATE.md). Не переносите теги опубликованных версий.

## Сообщение об ошибке

Нужны SHA пакета, версия ОС, этап сбоя, тип входа, обезличенные настройки, фрагмент журнала и способ повторения. Не публикуйте SSH-ключи, токены, персональные данные или закрытые измерения. По возможности приложите небольшой разрешённый контрольный пример вместо всего архива станции.
