# SatDump для Astra Linux

Ветка `release/1.2.2`: декодирование спутниковых записей, цветокомпозиции, паспорта продуктов и локальная веб-галерея. Station предназначена для Astra Linux 1.6 x86_64; Desktop для Astra 1.7 поставляется отдельным пакетом.

[Установка](docs/ru/station/INSTALL.md) · [Источники](docs/ru/station/INPUTS.md) · [Настройки](docs/ru/station/CONFIGURATION.md) · [UTC и планировщик](docs/ru/station/UTC_AND_SCHEDULER.md) · [Вся документация](docs/README.md)

## Состав Station

`SatDump` декодирует записи и обрабатывает сохранённые каналы: выполняет калибровку, RGB-синтез, применение цветовых шкал и геопривязку. Обработчик станции обнаруживает входные файлы, ведёт очередь SQLite, запускает движок на рабочей копии и публикует результаты. Сайт показывает готовые изображения и JSON-паспорта; он не восстанавливает спектральные каналы из обычной RGB-картинки.

```text
Файлы приёмника → проверка готовности → очередь → SatDump
→ научный архив + PNG/JSON/превью → каталог → веб-галерея
```

Устанавливаются три службы systemd: `satdump-worker`, `satdump-web`, `satdump-control`. Для варианта с nginx добавляется внутренняя служба `satdump-board`. Публичная галерея доступна на `http://127.0.0.1:8090/`, каталог — `/api/v1/board`. Управляющий API слушает только `127.0.0.1:8091` и требует токен.

Встроенная галерея включена в исходники и новый собираемый пакет: отдельный проект сайта для её запуска не нужен. Дополнительный интерфейс можно подключить через `satdump-station ui-deploy`.

## Автономная работа

Полный бинарный пакет содержит движок, его ресурсы, отдельное окружение Python/Pillow и файлы галереи. На целевой станции не требуются Docker, Node.js, pip или компилятор. Установщик не скачивает зависимости. nginx необязателен и используется только при наличии в ОС.

Обработчик запускается без доступа к сети; сетевое обновление TLE отключено. Для обработки нужны локальные данные, каналы и необходимые орбитальные сведения. Их наличие и актуальность проверяются для конкретного источника. Сетевые каталоги монтируются средствами ОС.

**Сборка из чистого клона — другой режим:** для подготовки сборочного окружения нужны зависимости и загружаемые компоненты либо заранее подготовленный кеш. Android имеет отдельный подмодуль зависимостей, не используемый Station. Исходный ZIP GitHub не является бинарным установщиком.

## Установка и проверка

Используйте архив Station и соответствующий файл `.sha256` из [списка выпусков](docs/ru/RELEASES.md). После проверки суммы распакуйте архив и выполните внутри него:

```bash
sudo ./install.sh
```

Адрес внешнего доступа задаётся явно; по умолчанию сайт доступен только на самой станции. Встроенный сервер предназначен для localhost или доверенной локальной сети, не для прямого размещения в интернете.

После установки:

```bash
systemctl is-active satdump-worker satdump-web satdump-control
satdump-station time-status
sudo satdump-station doctor
sudo satdump-station status
```

Опубликованные бинарные выпуски сохраняют свой состав. Изменения этой ветки, включая исправления UTC и встроенную галерею, попадут в установочный архив после его сборки и приёмки; наличие изменений в исходниках не обновляет ранее скачанный пакет.

## Входные каталоги

Пути задаются в массиве `sources` центральной конфигурации. Поддерживаются `image` — готовые PNG/JPEG, `product` — сохранённые наборы `product.cbor` с каналами, `pipeline` — записи или кадры для выбранного конвейера. При установленном управляющем API его активная ревизия имеет приоритет над исходным `station.json`.

Шаблон `meteor_iq` выключен: перед включением необходимо задать фактический формат записи и частоту дискретизации. Маркер готовности создаёт приёмник после завершения записи. Обход каталогов выполняется между заданиями; очередь и готовые результаты сохраняются после перезапуска. [Настройка поступления файлов](docs/ru/station/INPUTS.md).

## UTC

Время наблюдения хранится отдельно от времени изменения файла и публикации. Подписи, JSON-поля времени и журналы Station используют UTC. Задержки планировщика и проверка работоспособности не зависят от изменения системной даты. Сами часы синхронизирует служба ОС; результат проверяется командой `time-status`. [Форматы и настройка часов](docs/ru/station/UTC_AND_SCHEDULER.md).

## Разработка

Из корня исходников:

```bash
python3 -m unittest discover -s tests/station -v
python3 -m unittest discover -s tests/docs -v
python3 scripts/docs/check.py
```

Для тестов обработки нужен Pillow. Контрольные изображения и исполняемые файлы в тестах проверяют программные контракты, не качество декодирования реального радиосигнала. Порядок сборки и приёмки: [руководство](docs/ru/station/BUILD_RELEASE.md).
