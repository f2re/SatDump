# SatDump для Astra Linux

Ветка `release/1.2.2`: декодирование спутниковых записей, обработка каналов, цветокомпозиции, паспорта и локальная веб-галерея. Station предназначена для Astra Linux 1.6 x86_64. Desktop для Astra 1.7 поставляется отдельно.

## Как работает Station

```text
Завершённые файлы приёмника → очередь SQLite → рабочая копия → SatDump
→ каналы и отчёты → полные/компактные PNG + паспорта + превью → сайт
```

Источники бывают трёх видов: `image` публикует готовый PNG/JPEG; `product` пересчитывает набор каналов с `product.cbor`; `pipeline` декодирует запись или кадры выбранным конвейером. Калибровка и геопривязка выполняются только там, где их поддерживает прибор и достаточно исходных данных. Из обычной RGB-картинки каналы не восстанавливаются.

Пути находятся в `sources[].path` центральной конфигурации. Базовые настройки — `/etc/satdump-station/station.json`; сохранённая ревизия API — `/var/lib/satdump-station/control/active.json` — имеет приоритет для редактируемых полей. Она применяется между заданиями. Разрешённые корни и конвейеры задаёт администратор в `control-policy.json`.

Маркер `.ready` создаёт приёмник после завершения записи. Обход каталогов выполняется между заданиями: `poll_seconds` задаёт паузу в простое, а не предельную задержку обнаружения. Шаблон `meteor_iq` выключен; его формат и частота дискретизации требуют настройки. LRPT МСУ-МР и вход микроволнового радиометра МТВЗА — разные тракты.

## Полнота продукции и восстановление

Сохранённый CBOR сам по себе не доказывает наличие каналов. Декодер сообщает `no_data` при отсутствии полных строк; обработчик записывает созданные и пропущенные композиции в `processing-status.json`.

Для обязательного присутствия МТВЗА добавьте в существующий источник `product` или `pipeline` поле `"required_instruments": ["mtvza"]`. Наличие других изображений не заменит продукцию этого прибора. Без обязательного списка пригодная часть набора может публиковаться с предупреждением. `done` означает публикацию, а не научную приёмку всех продуктов.

При восстановлении очереди проверяется наличие и ненулевой размер файлов готовых публикаций. Неполный набор помещается в приватный карантин и пересоздаётся из доступного исходника. Обычная остановка службы не расходует попытку; тайм-аут и аварийное завершение остаются ошибками. [Диагностика, отчёты и ограничения](docs/ru/station/MTVZA_PROCESSING.md).

## Установка и проверка

Скачайте полный архив Station и его `.sha256` из выбранного выпуска. После проверки суммы распакуйте архив и выполните внутри него:

```bash
sudo ./install.sh
```

Устанавливаются `satdump-worker`, `satdump-web`, `satdump-control`. Вариант с nginx дополнительно использует внутреннюю службу `satdump-board`. Встроенная галерея доступна на `http://127.0.0.1:8090/`, каталог — `/api/v1/board`. Управляющий API слушает только `127.0.0.1:8091` и требует токен. Он не является открытой административной страницей сайта.

```bash
systemctl is-active satdump-worker satdump-web satdump-control
satdump-station time-status
sudo satdump-station doctor
sudo satdump-station status
```

Публичный доступ задаётся явно. Встроенный сервер предназначен для localhost и доверенной ЛВС. Дополнительный интерфейс подключается через `satdump-station ui-deploy`; по умолчанию отдельный проект сайта не нужен. [Галерея, состояния и встроенная справка](docs/ru/station/WEBSITE.md).

## Автономность и время

Бинарный пакет содержит движок, ресурсы, Python/Pillow и сайт. На целевой станции не требуются Docker, Node.js, pip или компилятор. Установщик не скачивает зависимости. nginx необязателен и используется только при наличии в ОС.

Обработчик работает без сети, обновление TLE отключено. Входные данные и необходимые орбитальные сведения должны быть доступны локально. Сетевые папки монтирует ОС. Первичная сборка из исходников требует зависимостей и загружаемых компонентов либо подготовленного кеша. Исходный ZIP GitHub не является установочным пакетом.

Время наблюдения, изменения файла и публикации разделены. Подписи и журналы Station используют UTC; интервалы очереди измеряются монотонными часами. Часы синхронизирует служба ОС, не SatDump. `time-status` различает подтверждённую, отсутствующую и неизвестную синхронизацию.

## Разработка

```bash
python3 -m unittest discover -s tests/station -v
python3 -m unittest discover -s tests/docs -v
python3 scripts/docs/check.py
node --test tests/web/*.test.js
```

Для Python-тестов нужен Pillow; Node.js нужен только для тестов сайта на машине разработчика. Сборка с `BUILD_TESTING=ON` добавляет `satdump-mtvza-reader-test`; сквозные сценарии находятся в `tests/meteor/test_native_products.py`. Они используют настоящий движок и синтетические кадры, не подтверждая точность реального радиоприёма, калибровки или геопривязки. [Сборка и выпуск](docs/ru/station/BUILD_RELEASE.md).
